# 지원기관 개선 적용 및 복구

대상: AYF, FoWI, KHIDI, KNPS, KNF, KOHI, CAYF. KYWA 운영 커밋은 유지한다. 실제 진행 상태는 HANDOFF.md를 먼저 확인한다.

## 설정과 배포

- `ORGANIZATION_ID`와 기관별 저장소 설정을 유지한다. AYF는 제공된 전용 시트와 기존 KYWA 공용 사진 폴더를 사용한다.
- `experience_version=2`는 개선 입력·사진·로그인·출력을 사용한다. `branding.technical_support=true`는 7개 기관의 공동 표시와 지원 안내를 켠다. 공통 인증정보는 서버 환경변수에만 둔다.
- 평가 기준 버전은 변경하지 않는다. `prompt_profiles/`는 기관 원본 지침, `prompts.institution_prompt`는 기관·점수표·출력 스키마를 결합한다. AYF는 CAYF 지침을 사용한다.
- 기존 24열도 읽고 쓸 수 있는 코드를 먼저 배포할 수 있다. 이관은 반드시 해당 서비스의 신규 앱 쓰기를 중지한 상태에서 한다. AYF는 준비 모드에서 빈 시트를 초기화한 뒤 운영 모드로 배포한다.
- AYF → FoWI → KHIDI → KNPS·KNF·KOHI·CAYF 순서로 개별 배포/검증한다. 자동 배포나 Blueprint 전체 동기화로 KYWA를 변경하지 않는다.

## 사본 검사와 이관

공개 사진 폴더에는 업무 기록 사본을 만들지 않는다. 편집 권한이 있는 비공개 공유 드라이브 폴더에 전체 파일 사본을 만들고 공개 권한이 없는지 확인한다. 인증 JSON·API 키·실제 평가·사진·보고서는 공개 GitHub 업로드 대상이 아니다.

`backend.migrate_partners.migrate(settings, apply=False)`로 계획을 읽는다. `apply=True`는 전체 값/서식/조치이력의 로컬 백업 및 원본 탭의 숨김 사본을 만든 뒤 관리 5열을 이관한다. 먼저 사본 설정으로 실행하고 운영 설정과 혼동하지 않는다. 설정의 시트 ID·탭·기관을 실행 전 출력해 확인하되 인증정보는 출력하지 않는다.

이관은 평가ID·평가기준버전·처리상태·수정버전·시스템데이터만 평가표에서 제거한다. KHIDI D열 ‘이름’과 다른 기관의 성명 열은 유지한다. `visible_layout.py`가 물리 열과 내부 19열을 연결한다. `_시스템관리`에는 이력/요청/행 식별정보가 남는다. 기존 값·사진·이력 대조 실패 시 쓰기를 재개하지 않는다.

완료 후 같은 도구를 다시 실행해도 이미 19열이면 삭제를 반복하지 않고 식별정보 준비 상태만 검사한다. Google API 한도는 공통 서비스 계정에서 공유하므로 사본 시험/이관은 순차 수행한다.

## 운영 확인과 복구

신규 제출·동일 요청 재시도·공식 사진 링크·한국 시각/서식·표 범위, 직접 수정·행 삭제 후 추가, 조치/재평가·세 보고서 제목/파일명과 기관 점수표를 확인한다. 시험 기록만 정리하고 기존 기록·사진·이력의 보존을 대조한 뒤 쓰기를 재개한다.

실패 시 서비스의 신규 쓰기를 중지한다. 실패 이후 추가된 행·요청·사진은 별도로 보관한다. 전체 파일 백업을 기준으로 평가표·숨김 관리·조치이력·행 메타데이터를 같은 시점으로 복구하고 추가분을 중복 없이 대조한다. **19열 구조에서 구버전 코드만 단독 롤백하지 않는다.** 이미 저장된 요청은 같은 요청번호로 복구하고 새 요청으로 중복 전송하지 않는다.

수동 행 삭제·전체 내용 지우기·셀 값 수정은 지원한다. 일부 열만 정렬하거나 다른 평가의 셀을 섞는 작업은 지원하지 않는다. 사진 링크 호버 미리보기는 Google UI와 권한에 의존하며 링크 형식만으로 성공을 단정하지 않는다.
