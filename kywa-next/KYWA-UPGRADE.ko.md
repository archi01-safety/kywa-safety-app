# KYWA 개선 버전 운영·복구 안내 (2026-11-02)

이 버전의 새 사진 처리, 진행 팝업, 프롬프트와 PDF/HWPX는 ORGANIZATION_ID=kywa에서만 사용합니다. 다른 기관은 기존 배포 커밋을 유지하며 자동 배포와 Blueprint 자동 동기화를 켜지 않습니다. 무료 인스턴스 절전 방지 호출을 추가하지 않습니다.

## 사진과 보고서

사진은 실제 내용으로 JPEG/PNG/WebP/HEIC/HEIF를 판별합니다. 20MB와 5천만 화소 제한이 있고, 방향을 보정한 1600px 이하 JPEG를 만듭니다. Linux는 libvips/libheif, Windows 개발 환경은 libheif 기반 pillow-heif를 사용합니다. 분석 전에 AI가 얼굴 위치를 찾고 여유 영역을 모자이크합니다. 탐지 실패 시 위험 분석과 제출은 중단됩니다. 자동 탐지는 완벽한 비식별화를 보장하지 않으므로 사용자는 최종 사진을 확인할 수 있습니다. 분석 완료 시 기본 체크는 수동 확인 이력으로 기록하지 않습니다.

보고서 생성은 관리자 세션별 작업 API를 사용합니다. 첫 PDF/HWPX 요청에서 집계는 서버가 계산하고 AI는 총평·상세 요약만 작성합니다. 전용 성명·사진·평가 ID는 이 AI 요청에서 제외하며 결과를 별도 검증합니다. 같은 조건·기록 버전은 생성 결과를 공유합니다. 작업은 메모리에 최대 30분 보관되므로 서버 재시작 시 다시 생성합니다. 한글은 편집 가능한 문단·표와 개별 사진으로 구성하며 페이지 전체를 이미지로 붙이지 않습니다. 문단형 writer는 의미 단위 문단·실제 점수표·2열 사진표를 생성합니다. backend/assets/hwpx-semantic-source.zip에 생성 소스와 라이선스를 보관하며 SETUP.md에 재빌드 절차가 있습니다. PDF의 좌표별 텍스트를 HWPX로 변환하지 않습니다.

진동은 navigator.vibrate 지원 기기에서 완료 시 45ms 한 번 요청합니다. iOS 등 미지원 브라우저에서는 시각 효과만 사용합니다. 모션 감소 환경에서는 애니메이션을 줄입니다. 실제 기기에서 진동 발생 여부는 별도 확인해야 합니다.

## 시트 이관 절차

1. 먼저 인증정보가 연결된 **검증용 사본 파일**에서 아래 도구를 실행합니다. 운영 ID가 아닌지 확인합니다. 대상 파일 ID는 필수 인자이며 기관 기본 ID로 자동 대체하지 않습니다. 서비스 계정 JSON은 환경변수/로컬 비밀 파일로만 제공하고 로그나 소스에 넣지 않습니다.
2. `python -m backend.migrate_compact --spreadsheet-id 대상파일ID`로 24/20/19열 헤더와 건수·조치이력을 검사합니다. `--apply`가 없으면 변경하지 않습니다.
3. 새 앱 관리자 세션과 CSRF로 `POST /api/admin/storage-maintenance`에 Form `enabled=true`를 전송한다. 활성 쓰기가 끝난 뒤 최대 30분의 신규 쓰기 중지가 적용된다. 시간 내에 이관·검사를 마치고 `enabled=false`로 해제한다. 먼저 `python -m backend.migrate_compact`의 인자가 운영 대상인지 확인한 뒤 `python -m backend.migrate_compact --spreadsheet-id 대상파일ID --apply`를 실행합니다. Streamlit의 일반적인 행 추가는 지원하지만 수동 정렬·행 삭제·행 이동·기존 값 편집은 지원하지 않습니다. 이관 중 관리 데이터 수정도 중지합니다.
4. 도구는 값·서식·수식·메모·조치이력을 `local-data/migration-backups`에 저장하고 원래 평가 탭을 숨김 백업으로 복제합니다. 뒤이어 한 번의 원자적 요청으로 `_시스템관리` 생성, 관리 정보 작성, 5개 열(평가ID·평가기준버전·처리상태·수정버전·시스템데이터) 삭제, 기존 기준 행의 열별 서식 및 Roboto 10pt 복원, Asia/Seoul·ko_KR 설정, ISO 문자열의 실제 날짜값 변환, Form_Responses 표 범위 확장을 처리합니다.
5. 평가 탭은 A:R 원래 항목 + S 제출자 성명으로 남습니다. 숨김 관리 탭에는 행 위치·해시·평가 정보·요청 복구 정보를 보관합니다. 긴 관리 정보는 셀 글자 수 제한 이내로 여러 셀에 나누어 저장합니다. 숨김은 보안 권한 경계가 아니므로 파일 편집 권한은 기존 관리자에게만 제공합니다.
6. 이관 결과의 건수·점수·사진 링크·성명·평가 ID·조치 연결을 대조하고 새 제출/중복 재시도/기존 행 개선조치/재평가/보고서를 확인한 뒤 쓰기를 재개합니다. 도구 재실행 시 이미 이관된 구조를 확인하고 재삭제하지 않습니다.

새 코드에는 기존 24/20열 저장 호환 경로가 남아 있습니다. 코드 배포만으로 열이 삭제되지는 않습니다. 실제 사본 검증과 운영 이관 결과를 확인하기 전에는 저장 구조 개선이 배포 완료되었다고 표시하지 않습니다.

## 저장 장애와 복구

신규 요청은 관리 탭에 먼저 기록한 뒤 Google의 실제 행 추가 위치를 확인합니다. 응답이 유실되면 기록 내용과 위치를 다시 대조합니다. 후보가 없거나 여러 곳이면 새 행을 임의로 추가하지 않고 관리자 확인 오류로 멈춥니다. 네트워크 오류 시 사용자는 같은 요청으로 재시도해야 하며, 새로운 요청을 만들어 반복 제출하지 않습니다.

이관 후 문제가 발견되면 먼저 새 앱 쓰기를 중지합니다. 운영 탭·숨김 관리 탭·조치이력을 **현재 상태 그대로 별도 백업**합니다. 이관 이후 제출/조치가 없는 경우에만 이관 전 백업으로 즉시 복귀할 수 있습니다. `-latest-values.json`에는 백업 복제 도중 추가된 Streamlit 행까지 들어 있으므로 최초 백업 탭만 되돌리면 안 됩니다.

복귀 시 숨김 백업 탭의 값 영역을 `-latest-values.json`의 이관 전 열 수의 전체 값으로 복원하고, 현재 평가 탭은 삭제하지 말고 `_이관후_보존_날짜`로 이름을 바꿉니다. 복원한 탭을 기존 평가 탭 이름으로 바꾸고 숨김을 해제합니다. 조치이력은 변경하지 않습니다. 건수·사진 링크·점수·성명·평가 ID·조치 연결을 대조한 뒤 기존 24열 호환 코드로 재개합니다. 이관 이후 제출이나 조치가 있다면 최신 관리 정보로 해당 기록을 먼저 합쳐야 하며, 과거 백업으로 덮어쓰지 않습니다.

## 현재 검증 상태

최신 상태·배포 커밋·다음 작업은 HANDOFF.md, 변경 이력은 CHANGELOG.md를 따른다. 2026-10-30 공유 드라이브의 검증용 사본에서 138건과 조치이력 3건의 이관 및 신규/Streamlit 제출·재시도·개선조치 연결을 검증했다. 서비스 계정 권한 재부여는 필요하지 않았다. 별도 개인 파일 생성 대신 기존 공유 드라이브 안에서 Drive files.copy를 사용했다.

2026-11-02 로컬 백엔드 180개, 프런트엔드 단위 13개 및 Next.js 빌드를 통과했다. 문단형 HWPX는 한글 2020의 실제 PDF 출력으로 16건 9쪽, 30건 16쪽을 확인했다. 실제 기록을 사용한 검증 파일과 백업은 비공개 local-data에 보관한다.

운영 이관 및 최신 코드 배포는 아직 완료로 처리하지 않는다. 한글 2014, 실제 모바일 기기의 물리적 진동은 별도 확인 대상이다.
