# 8개 기관 v1.1 사진·조회·평가 개선

## 현재 상태

`feature/photo-review-v1.1`은 2026-11-10 운영 소스 b180b29에서 분리한 후보 브랜치다. 운영 배포 완료 여부는 HANDOFF.md와 기관별 releases/ 매니페스트를 따른다. 기능 후보 a0b4177, HTML 재확인 보완 54a789b, 단답형 정렬 보완 329f2f8을 구분한다. 최종 운영 배포는 기관별 Live 기록으로 확인하며 코드가 존재한다는 이유로 운영 반영 완료라고 판단하지 않는다.

## 사진·상태·조회

기존 업로드 박스에서 선택·촬영·드래그 앤 드롭을 같은 경로로 처리한다. 최초 평가 최대 2장, 개선 후 최대 1장이다. 실제 형식 판별/정규화 후 각 사진을 AI 머리 탐지와 타원형 블러로 처리하고, 최초 두 사진을 한 현장의 분석 자료로 전달한다. 개별 제거·교체·대표 순서 변경을 제공한다. 처리 사진과 저장 사진이 같으며 원본을 Drive에 저장하지 않는다.

평가표 마지막 열에 `개선 전 사진 2`만 추가한다. 일반 19→20열, AYF 17→18열이며 KHIDI D열 이름과 Streamlit 기존 앞쪽 열은 바꾸지 않는다. 사진 링크는 Drive 공식 webViewLink를 유지한다. Excel은 최초 사진 옆에 추가 사진을 배치한다. PDF/HWPX는 실제 3장일 때만 개선 전①/개선 전②/개선 후 3열이며 나머지는 2열이다. 문단형 HWPX 및 붙임 최대 2건/쪽을 유지한다.

조치예정은 계획 필수·예정일 선택이며 AI 재평가 없이 저장한다. 조치 내용·실행 이력과 연결하고 완료는 담당자 확인으로 처리한다. 상태 표시에는 접수/조치예정/조치중/조치완료를 사용하고 저장된 기존 상태 문자열과 과거 등급을 일괄 변경하지 않는다.

조회가 0.3초 이상 걸리면 실제 작업명을 표시한다. 연속 선택은 이전 요청을 취소하고 최신 조건만 반영한다. 사진별 로딩·등록 없음·실패·재시도를 제공한다. 상태 코드/안전한 오류 코드/요청번호로 로그인·권한·충돌·입력·한도·외부 연결·시간 초과를 구분한다. 조회만 제한 재시도하며 저장은 같은 요청번호로 확인한다.

PIN 세션은 토큰 원문 없이 기관과 PIN 설정에 묶인 해시/절대 만료 시각을 숨김 관리에 보관한다. 서버가 재시작돼도 유효 세션을 복원하고 명시적 1시간 연장·로그아웃 폐기를 유지한다. 단일 worker/인스턴스 운영이 전제다. 변경 배포 직후 이전 방식 세션은 한 번 재로그인이 필요하다. 임시 사진·초안·보고서 작업까지 서버 재시작 후 복원하는 기능은 포함하지 않는다.

## 내부 세부 판정

내부 가능성 1~15는 노출 빈도·접촉 가능성·안전조치 효과·위험 상태의 명시된 조합으로 계산한다. 내부 피해규모 1~20은 예상 피해 종류(경미/비휴업/휴업/사망·장애)와 범위를 조합한다. 두 단계의 곱은 1~300이다. 가능성 3단계, 피해규모 5단계씩 공개 빈도·강도로 환산한 뒤 기관별 확정 평가표로 공개 점수·등급을 계산한다. 내부 곱을 단순 비례로 20점에 나누지 않는다.

AI는 분류·장소·위험 원인/피해·대책·법령 후보와 정해진 관찰 항목만 추출한다. 관찰 추출은 temperature=0과 엄격한 JSON 스키마를 사용한다. 확인되지 않은 사실은 unknown으로 두고 짧은 선택 질문으로 확인한다. 같은 소유자/기관/모델/프롬프트/기준/현장/정규화 원본 사진/설명 조합의 관찰 결과는 최대 30분 재사용한다. 동일 조건 동시 요청도 하나로 합친다. 다른 제출 건의 ID는 합치지 않는다.

경미한 손상 제한은 FoWI 4점, KHIDI 5점, 나머지 6점을 유지하되 사망·추락·감전 또는 직접 노출 등의 관찰을 무시해 적용하지 않는다. 내부 수치·근거는 숨김 관리에만 저장하고 공개 API/화면/Excel/PDF/HWPX에 포함하지 않는다. 서버 점수 확정은 계산의 일관성을 높이는 장치이며 사진 밖 사실이나 법적 적합성까지 인증하지 않는다. 같은 사진의 캐시 일치와 다른 각도 사진의 사실 판정 일치는 별도로 검사한다.

`DETAILED_RISK_ENABLED=false`가 기본이다. 8개 기관 300개 조합의 매핑·경계값 검사는 실제 담당자 판단과의 일치도 검사를 대신하지 않는다. 반복 모델 관찰과 담당자 대조를 완료한 기관에서만 활성화한다. 과거 평가는 다시 계산하지 않는다.

## 이관·검증·배포

1. 현재 운영 소스/기관 설정과 헤더를 확인하고 기관별 v1.0.0 기준 태그를 등록한다.
2. 비공개 사본에서 `python -m backend.migrate_photos`로 계획을 확인한다. `--apply` 때 전체 값/서식/행 식별/관리/이력을 비공개 로컬 JSON과 같은 파일 숨김 백업 탭에 보관하고 마지막 열만 추가한다. 미완료 저장이나 기존 값 충돌이면 중단한다.
3. 기존 행·Streamlit 추가·사진 2+1·같은 요청 재시도·조치예정·직접 편집/삭제·재시작 인증·3종 출력·복구 시 신규 데이터 보존을 확인한다.
4. PC/모바일, 실제 한글 편집/출력, 백엔드·프런트·CI·Docker 검증을 완료한다. 법령 API 실인증 검사는 LAW-API-SETUP.ko.md를 따른다.
5. 기관별 최신 백업 후 신규 앱 쓰기를 `/api/admin/storage-maintenance`로 잠시 중지한다. 이관과 새 커밋 개별 배포를 연속 수행하고 운영 시험을 완료한 뒤 재개한다. 전체 Blueprint 동기화나 절전 방지 호출은 추가하지 않는다.

## 기관별 버전 복구

기관별 `releases/<기관>/vX.Y.Z.json`과 `<기관>/vX.Y.Z` 태그에 소스·설정/프롬프트 해시·기준·시트 구조·검증·배포를 기록한다. 이미 등록한 버전이 가리키는 소스를 바꾸지 않는다. 배포 서비스와 다른 기관의 버전을 함께 되돌리지 않는다.

복구 전에는 현재 시트 전체를 다시 백업한다. v1.0.0처럼 추가 사진/계획을 모르는 코드로 돌아갈 때는 현재 도구의 `python -m backend.rollback_photo_schema`로 계획을 확인하고 쓰기 중지 후 `--apply`한다. 추가 사진·계획·내부 판정을 숨김 `rollback-v1.1` 관리 기록과 백업에 보존하고 현행 모든 행/ID·기본 값/이력을 남긴 채 마지막 추가 열만 제거한다. 조치예정은 구버전에서 접수(기존 조치가 있으면 조치 중)로 표시하고 원래 상태/계획은 보관한다. 과거 전체 시트 백업으로 운영 파일을 덮어써 복구 이후 제출을 잃어버리는 방식은 사용하지 않는다.

상위 버전으로 복귀할 때는 추가 열 이관 후 `rollback-v1.1`의 보관 값을 현재 ID·수정 버전·대표사진과 대조해 복원한다. 복구 후 사용자가 수정한 계획·사진·평가에 보관본을 무조건 덮어쓰지 않는다. 충돌 항목은 별도로 확인한다. 관리 정보·시트 구조가 다른 상태에서 코드만 먼저 되돌리지 않는다.

## 담당자 판정 검토

사용자 확인 결과 담당자 확정 사례는 아직 없다. 합성 12사례 검토표를 제공하며, 앞의 4사례는 실제 모델의 독립 3회 반복 결과를 기입하고 나머지는 미분석 공란으로 둔다. 담당자가 빈도·강도·판단 이유를 확정한 뒤 대표 사진 각도를 추가해 비교한다. 반복값 일치가 실제 정확도나 과소평가 없음의 증명은 아니다. 그 전까지 내부 세부 판정은 비활성을 유지하고 기존 기관별 평가 경로를 사용한다.

## 추가 서식 보완

단답형 열의 기존/신규 Google 행과 내보내기 Excel은 가운데 정렬하고 긴 설명은 왼쪽 정렬한다. Google native table 확장 후 정렬 확정을 같은 요청에 포함하며 데이터·다른 서식은 유지한다. 재실행 가능한 정렬 도구와 사본 검사는 SHEET-EDITING.ko.md를 따른다.
