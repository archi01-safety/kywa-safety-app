# v1.2.1 JPEG·아이폰 대표사진 업로드 보완

## 확인된 원인

일반 `.jpeg`는 기존 코드와 운영 선택창에서도 허용됐다. 다만 안내에는 JPG만 표시돼 있었다. 사용자가 제공한 실제 실패 파일을 검사하니 JPEG 시그니처를 가진 **8프레임 MPO**였다. 기존 허용 목록이 `JPEG/PNG/WEBP`만 포함해 파일 내부 형식 `MPO`를 거부했다. 기준 운영 커밋 aa30598의 정규화 함수에서도 이 원본의 거부를 재현했다.

JPEG 내부의 보조 사진을 읽는 과정에서 MPO로 식별될 수 있다. [Pillow MPO 문서](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#mpo)와 [아이폰 JPEG 관련 기록](https://github.com/python-pillow/Pillow/issues/7879)을 참고했다. Live Photo 자체는 정지사진과 동영상으로 구성된다([Apple 문서](https://developer.apple.com/documentation/livephotoskitjs)). 이번에는 웹에서 선택된 대표 정지사진을 처리하며 Live Photo 동영상 저장·분석 기능을 추가하지 않는다.

## 수정 내용

- 실제 이미지 디코더가 MPO로 식별한 JPEG도 허용하고 `seek(0)`으로 대표 정지사진만 정규화한다. 보조 이미지와 메타데이터는 저장 사진에 포함하지 않는다.
- 기존 방향 보정·RGB 변환·긴 변1,600px·20MB/5,000만 화소 제한과 얼굴 블러 처리 흐름을 유지한다. 레거시 정규화 경로도 대표 JPEG를 같은 방식으로 읽되 기존 용량/화소 제한은 유지한다.
- 공통 사진 선택창은 `image/*`와 사진 확장자를 사용하고, 실제 허용 형식은 서버가 파일 내용으로 확인한다. 최초 최대2장·개선 후 최대1장과 교체/드롭에 같은 처리를 사용한다.
- 화면과 오류 안내에 `JPG/JPEG`, `HEIC/HEIF`를 명시한다. 입력창의 선택값은 업로드가 끝난 뒤 초기화한다.
- 기관별 Google 저장소·시트 구조·평가표·프롬프트·이름 수집·권한·PIN·환경변수는 바꾸지 않는다. GitHub Actions는 중지 상태를 유지한다.

## 검증

- 제공된 원본은 4,116,151바이트·4032×3024·MPO8프레임이다. 수정 후 **523,249바이트·1600×1200·단일 JPEG**로 변환됐고 EXIF를 제거했다.
- 같은 원본으로 로컬의 8개 기관 설정 모두 `/api/photos/prepare`와 미리보기 HTTP200을 확인했다. 외부 AI나 운영 Google 저장소에는 원본을 전송하지 않았다.
- 합성 일반/대문자/혼합 확장자·빈 MIME/일반 바이너리 MIME·프로그레시브·EXIF 회전·MPO2/8프레임 및 손상/GIF/SVG/MOV 차단, 기존 사진/얼굴/저장 회귀를 합쳐104개 검사했다.
- 모바일 크기의 실제 브라우저에서 최초2장(MPO JPEG+회전 JPEG), 개선 후1장, 제공 원본의 교체 업로드·1600×1200 미리보기를 확인했다. 제공 사진 화면은 캡처하거나 공개하지 않았다. 확인 뒤 홈 초기화로 임시 사진을 지우고 시험 서버를 종료했다.
- root 및 `/apps/kywa-safety` 정적 화면을 webpack/TypeScript로 빌드했다. 실제 아이폰의 Safari를 직접 제어한 시험과 실제 AX 서버 등록은 수행하지 않았다.

검증 소스0a1c236을 8개 기관에 배포하고 Live를 확인했다. 운영에서도 합성MPO8프레임 사진의 준비·미리보기 HTTP200과 대표1장/메타데이터 제거를 확인한 뒤 각 세션의 임시 사진을 초기화했다. 원본은 공개 테스트 자료나 ZIP에 포함하지 않는다. 사용자가 직접 삭제하기로 변경했으므로 원본은 추가로 삭제/이동하지 않았다. 보관하는 회귀 자료는 프로그램으로 생성한 합성 이미지와 이미지가 없는 검증 정보다.
