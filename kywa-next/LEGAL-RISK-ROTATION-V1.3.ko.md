# v1.3 법령 번호 보정·기관별 세부 판정·사진 회전

## 적용과 데이터 보존

대상은 KYWA·AYF·FoWI·KHIDI·KNPS·KNF·KOHI·CAYF다. 공개 점수표와 당시 평가값은 유지한다. 공개 평가 탭은 일반20열/AYF18열 그대로이며 운영 셀의 일괄 수정이나 열 이관을 하지 않는다. 배포 전 전체 파일 복사본과 GridData/행 메타데이터/숨김 관리/조치이력을 비공개 local-data/v13/preflight/에 준비했다. 백업 식별정보는 공개하지 않는다.

## 법령 처리

현행 시행본에서 제시된 조문 번호가 존재하지만 제목이 다르면 같은 법령의 본문을 조회한다. 표기를 정리한 제목이 정확히 일치하는 유효 조문이 하나일 때만 그 번호로 보정한다. 없는/삭제된 조항, 제목 미일치/중복, 확인되지 않는 항·호는 공식 검색 링크를 유지한다. 여러 근거는 독립적으로 처리하고 이미 정확한 번호를 제목 중복 때문에 바꾸지 않는다. API 장애도 다른 평가의 분석을 중단시키지 않는다.

신규 분석은 보정 문구를 초안에 확정하고 같은 문구를 저장한다. 화면에는 최종 문구와 링크만 제공한다. 보정 전후 정보는 `_internal_law`로 보관하고 공개 응답에서 제거한다. 과거 기록은 조회/출력 사본만 보정하며 원래 시트 값·수정 버전을 바꾸지 않는다. `/api/law-links`는 기존 items/configured와 함께 최종 text를 반환한다. 신규 초안은 뒤늦은 법령 재조회로 저장 문구와 달라지지 않게 고정한다. 조문 존재·제목 확인은 현장의 법적 적합성 인증이 아니다.

## 기관별 세부 판정과 선택 질문

서버 기준은 `backend/risk_profiles/<기관>.json`, 계산은 `backend/risk_profiles.py`다. 공개 빈도1~5를 각3단계, 강도1~4를 각5단계로 나눠 내부15×20조합을 만든다. 내부 곱1~300을 단순히20점으로 비례 환산하지 않는다. 공개 빈도·강도로 묶은 다음 기존 기관 평가표로 점수·등급을 확정한다. 300개의 서로 다른 정수값을 모두 사용한다는 뜻은 아니다.

기관별 원본 설명/프롬프트 버전, 가중값, 미확인 기본값, 경미 제한, 기준/계산 소스 해시를 보관한다. FoWI의 측정 노출수준·하루 작업시간·소음 기준은 해당 기관에만 적용하며 사용자 설명에 실제 수치와 단위가 있을 때만 사용한다. FoWI4점·KHIDI5점·나머지6점의 경미 제한은 중상/사망 기전을 덮어쓰지 않는다. 보호 규칙은 분류명만으로 발동하지 않으며 구체적인 위험 기전과 현재 활성 상태를 확인한다.

미확인 사실과 적용 기본값을 내부에 구분한다. 우선 초안을 반환하며 등급에 영향을 주는 쉬운 질문을 전체 분석당 최대2개만 선택적으로 제공한다. 미응답/잘 모르겠어요도 제출을 막지 않는다. 응답하면 추가 AI 호출 없이 새 초안 ID로 계산하고 이전 초안의 신규 제출은 거부한다. 같은 확인 요청 재시도는 같은 후속 초안을 반환한다. 수동 편집한 장소·위험상황·감소대책은 화면에 보존한다.

내부 판정/기본값/근거는 `_internal_risk`로 기존 숨김 구조에 보관한다. 앱·공개 API·통계·Excel/PDF/HWPX에는 포함하지 않는다. 동일 입력 관찰 재사용은 세션 소유자·기관·현장·사진·모델·프롬프트·기준 버전별로 제한한다. 재시작을 넘는 영구 동일성이나 실제 사진의 모든 구도에서 같은 점수를 보장하지 않는다.

## 사진 회전

기존 박스에서 최초2장/개선후1장을 각각 좌우90도 회전한다. `POST /api/photos/{id}/rotate`는 request_id와 quarter_turns(-1/1)를 받고 새 소유자 귀속 사진 ID/미리보기를 반환한다. 재시도는 회전을 중복 적용하지 않는다. 정규화한 기초 JPEG와 누적 각도에서 매번 변환하고0도 복귀 시 같은 기초 바이트를 사용한다.

회전하면 이전 분석/재평가 초안을 무효화하고 얼굴 탐지·블러·분석을 다시 수행한다. 실패하면 기존 사진을 유지한다. 홈 초기화는 기초/회전/블러 사진도 정리한다. 기존 Drive 사진과 파일명 규칙은 변경하지 않는다.

## 재현·검증과 복구

- `python scripts/build_risk_profiles.py`: 기존 기관 기준에서8개 JSON 생성. 기준 수정 시 버전도 올리고 재검증한다.
- `python scripts/risk_backdata.py`: 기관별60사례(작성36/별도검증24)와300개매핑 생성. 기본 출력은 비공개 local-data/v13/backdata/다. 실제 제출 기록과 기존 AI값을 정답으로 쓰지 않는다.
- `python scripts/benchmark_risk_v13.py --key-file <비공개 경로> --output <비공개 출력>`: 기관별12사례×3회 캐시 없는 독립 호출. 키를 CLI에 직접 적지 않는다.
- 최종 반복288회는 모두 같은 공개 빈도·강도/합성 기대값을 보였고 중대 사례 과소평가는0건이다. 합성 카메라 정면/측면/근접48회도 일치했다. 실제 촬영 현장/전문가 정확도 검증과 구분한다.
- 중간 관찰 스키마의 API400과 화재 표지 사례 과대평가를 발견해 수정했다. 실패 결과는 비공개로 보존하고 보완 후288회 전체를 새로 실행했다.
- 8개기관 실제 법령 API에서37→38·항호·제목 불일치를 검사했다.8개기관 합성3장 보고서의 법령/방향/내부정보 제외를 검사했다. PC·모바일 브라우저는 KYWA 합성 환경에서 조작했고 기관별 API는8개를 검사한다.
- 로컬 검토 Excel8개는 작업공간 outputs/kywa-v1.3-20261116/내부판정검토/에 보관한다. 담당자 회신은 추후 보정 자료이며 이번 활성화의 필수 조건이 아니다. 다른 기관에 사례 작성을 요청하지 않는다.

v1.3은 검증된8개 기준을 기본 활성화한다. `DETAILED_RISK_ENABLED=false`는 기존 AI 빈도·강도 제안 경로로 복구하는 명시적 설정이다. 운영8개에 기존 강제값이 없음을 확인했다. 기본값은 새 소스 배포 시 적용되며 비밀번호·세션 키·인증 그룹은 바꾸지 않는다.

v1.2.1 복구 시 기관 태그를 확인하고 해당 기관만 배포한다. 환경변수를 명시적으로 등록한 환경은 false로 맞춘 뒤 구버전을 배포한다. 시트를 예전 백업으로 통째로 덮어쓰지 않으며 신규 제출·사진·숨김 판정/보정 이력을 보존한다. Actions는 재활성화하지 않는다. 실제 배포 SHA/Live는 releases/와 artifacts/render-deployments.json을 따른다.
