# 기관별 독립 운영·Google 연동 설정

공통 소스와 별도의 Render 무료 Docker 웹서비스를 사용합니다. 각 서비스는 `ORGANIZATION_ID`로 기관을 고릅니다. 첫 접속 대기를 수용하며 절전 방지 주기 호출을 추가하지 않습니다. 기관 설정을 찾지 못하면 시작을 중단하고 KYWA로 대체하지 않습니다.

## 서버 설정

공통 서비스 계정은 `kywa-safety-check@gen-lang-client-0053629470.iam.gserviceaccount.com`입니다. 서버의 `GOOGLE_SERVICE_ACCOUNT_JSON.client_email`이 이 계정과 다르면 시작·연동 검사를 중단합니다. `GOOGLE_DELEGATE_EMAIL`은 비웁니다.

- `ORGANIZATION_ID`: 위 표의 ID. 기관은 서버 설정으로만 선택하고 요청 파라미터로 바꾸지 않습니다.
- `SPREADSHEET_ID`, `DRIVE_FOLDER_ID`: 비워 두면 해당 기관 JSON의 `storage` 값을 사용합니다. 운영에서는 명시한 값도 기관 설정과 일치해야 합니다.
- `SHEET_NAME`: 환경변수를 생략하면 기관 기본값을 사용합니다. 타 기관 서비스에 KYWA 탭 이름을 복사하지 마세요.
- `HISTORY_SHEET_NAME=조치이력`: 기존 평가 탭과 다른 이름이어야 합니다.
- `APP_ENV=production`, `ALLOW_LEGACY_WRITES=true`: 운영 시트 백업·헤더 준비 후 사용합니다. `demo`는 가상 분석·로컬 저장입니다.
- `AUTH_MODE=pin`, `ADMIN_PIN_HASH`: 기존 비밀번호 방식. `scripts/set_admin_pin.py`로 만든 해시만 서버에 등록합니다.
- 기관마다 `APP_BASE_URL`과 `SESSION_SECRET`을 별도로 설정합니다. `GEMINI_API_KEY`, `GEMINI_MODEL`, `KOSHA_API_KEY`는 서버 환경변수이며 공통 키를 사용할 수 있습니다.
- Google 로그인 방식은 `AUTH_MODE=google`과 OAuth 설정, 기관별 `ACCESS_ACCOUNTS_JSON`이 필요합니다. 관리자 role은 admin, 담당자 role은 staff이며 시설 값은 그 기관 목록을 사용합니다.

`render.yaml`은 KYWA 운영용 설정안, `deploy/organizations.render.yml`은 7개 독립 서비스 설정안입니다. 파일만 추가해도 배포되거나 연동 검증이 끝나는 것은 아닙니다. 기존 서비스는 재생성하지 않고 설정과 배포 브랜치를 확인합니다. 무료 인스턴스 1개·Uvicorn worker 1개를 유지합니다.

## 브랜딩

`branding.primary`가 기관 원색입니다. 서버가 버튼·호버·다크/라이트 강조색과 대비를 계산해 `/api/bootstrap`에 공개합니다. 저장소 ID·인증 JSON·원본 출처 설정은 bootstrap에서 제외합니다. 로딩 전에는 중립 회색을 사용합니다. 확인된 로고가 없는 기관은 기관명을 표시합니다.

차콜 배경은 공통이며 선택 메뉴, 주요 버튼, 얇은 표시선·약한 빛 번짐만 기관색을 사용합니다. 버튼 글자와 강조 글자는 일반 텍스트 대비 4.5:1 이상을 기준으로 계산합니다. 위험·경고·완료 색상은 별도 CSS 변수입니다. 보고서와 인쇄 화면은 흰색을 유지합니다.

## 기관별 평가표

- KYWA: 기존 확정 6등급 및 고정 v1 평가표를 유지합니다.
- FOWI: 매우 낮음 1~2 / 낮음 3~4 / 보통 5~8 / 약간 높음 9~12 / 높음 13~15 / 매우 높음 16~20.
- KHIDI: 매우 낮음 1~5 / 낮음 6~11 / 보통 12~15 / 높음 16~18 / 매우 높음 19~20.
- CAYF·KNF·KNPS·KOHI: 가능한 점수 기준 매우 낮음 1~3 / 낮음 4~6 / 보통 8 / 높음 9~15 / 매우 높음 16~20. **15점은 높음**입니다.

기관별 `policy.p_levels`, `s_levels`, `cells`, `grades`, `prompt_guidance`를 사용합니다. 모든 p·s 조합을 명시하고 서버가 AI 제안의 최종 점수·등급을 확정합니다. `tone` 0·1은 초록, 2는 노랑, 3은 주황, 4·5는 빨강입니다. 기준 변경 시 반드시 `policy.version`과 필요하면 `prompt_version`을 올립니다.

새 기록에는 평가표 스냅샷과 버전을 저장합니다. 해당 기록의 재평가는 그 스냅샷을 따릅니다. Streamlit 원본의 과거 점수·등급은 그대로 읽으며 기준 버전은 `LEGACY-UNKNOWN`으로 표시합니다. 이 행에 새 개선조치를 시작할 때는 화면에 안내한 현재 기관 평가표를 적용하고, 관리 정보를 처음 저장할 때 스냅샷을 고정합니다. 원래 등급을 소급 계산하지 않습니다. 보고서에는 최초 기준과 재평가 기준을 구분합니다.

## 성명 입력

`submitter_name` 설정 예:

```json
{
  "mode": "required",
  "label": "제출자 성명",
  "notice": "소속과 초성 변환 성명은 제출자 확인을 위해 관리자 화면과 보고서에 표시됩니다.",
  "show_in_reports": true
}
```

- disabled: 입력창 없음. 이름을 포함한 제출 요청은 거부합니다.
- optional: 공란 분석·제출 가능. 입력했다면 동일한 한글 유효성 검사를 통과해야 합니다.
- required: 유효한 성명을 입력해야 화면에서 분석·제출할 수 있고, 제출 API도 공란을 거부합니다. 분석 API는 이름을 전혀 받지 않으므로 성명 입력 여부를 서버에서 확인하지 않습니다.
- 성명은 분석 전 **현장 정보** 영역에서 입력합니다. 입력창은 원본을 유지하고 바로 아래에 `홍㉠㉢으로 제출됩니다.`를 표시합니다. 한글 조합 중에는 오류를 표시하지 않으며 분석·제출을 잠시 막습니다.
- 공백을 모두 제거하고 NFC 정규화한 완성형 한글을 1~100글자까지 허용합니다. 첫 글자는 유지하고 나머지 **모든 글자**를 초성으로 바꿉니다. `홍→홍`, `김민→김㉤`, `남궁민→남㉠㉤`, `김하늘별→김㉭㉡㉥`. 복성도 예외 없이 첫 글자만 유지합니다. 쌍초성은 대응 원문자가 없어 `ㄲ·ㄸ·ㅃ·ㅆ·ㅉ` 그대로 표시합니다.
- 원본은 브라우저 입력 상태에만 두고 저장소·URL·로그에 기록하지 않습니다. 분석·재평가 요청에는 성명 필드가 없고, 제출 요청·중복 제출 확인 정보에는 변환값만 사용합니다. 제출 성공 시 이름과 제출 요청 식별 캐시를 비웁니다.
- 서버는 첫 글자 완성형 한글 + 초성 형식만 허용하며 원본 이름을 직접 전송하면 거부합니다. 잘못된 타입·길이·JSON 등을 포함한 검증 오류에서도 입력값을 응답·로그에 되풀이하지 않습니다. 한 글자는 원래 규칙상 원본과 제출값이 같습니다.
- 관리자/허용 담당자 평가 목록·상세·결과보고서 목록에는 변환값을 표시하며 공개 현황에는 성명을 포함하지 않습니다. 동일 초성이라도 평가 ID로 구분하고 제출자를 자동 병합하지 않습니다. 본인 인증 수단은 아닙니다.
- 기존 이름이 없으면 공란입니다. 원본 한글 성명이 있는 과거 기록은 조회·Excel·PDF 생성 시에만 변환하며, 조회로 원본 저장 데이터를 수정하지 않습니다. 지원하지 않는 과거 형식은 원본을 노출하지 않고 공란으로 표시합니다. 과거 데이터의 일괄 변환·삭제는 별도 이관 작업입니다.
- show_in_reports=true이면 Excel/PDF에 포함합니다. false이면 출력에서 제외합니다. 기존 이름을 삭제하는 기능은 아닙니다.
- 조치 수행자의 기존 인증 식별자는 제출자 성명과 별도로 유지합니다.

이 기능은 성명 입력란에 적용됩니다. 사용자가 상황 설명이나 사진에 직접 넣은 성명까지 자동으로 제거하는 기능은 아닙니다.

## 기존 시트 보존과 동시 제출

기관별 원래 13열, KHIDI의 D열 `이름`을 포함한 14열, KYWA 기존 A:R을 그대로 유지합니다. 열 이름을 바꾸거나 중간 삽입하지 않습니다. 없는 관리 항목만 오른쪽에 추가합니다. 일반 13열 기관은 N:W 관리 정보·X 성명, KHIDI는 O:X 관리 정보이며 성명은 기존 D열을 사용합니다. 별도 이름 열을 중복 생성하지 않습니다. 기존 추가 열이 있으면 매핑에 따라 그 오른쪽을 사용합니다.

Streamlit이 뒤에 추가한 행은 관리 정보 없이도 조회·통계·보고서에 포함됩니다. 시트·탭·행 위치·원본 내용으로 임시 ID를 만들므로 같은 내용의 두 제출을 합치지 않습니다. 개선조치 저장 직전에 원본 위치·내용·수정 버전을 다시 검사하고 관리 셀만 갱신합니다. 기존 원본 이름·날짜·사진 링크·점수는 덮어쓰지 않습니다. 새 시스템데이터의 이름은 변환값만 기록합니다.

지원하는 동시 운영은 **Streamlit 행 추가 + 새 앱 1개 서비스/worker**입니다. 수동 정렬·행 이동·삭제, 다른 앱의 기존 행 수정, 여러 새 앱 worker가 같은 시트를 수정하는 방식은 지원하지 않습니다. 이는 Google Sheets의 트랜잭션 DB 수준 잠금을 의미하지 않습니다. 충돌 오류가 나오면 새로고침하고 원본을 확인합니다.

공유 Drive의 새 사진 파일명·appProperties에는 기관 ID와 제출 요청 ID를 넣습니다. 사진 접근은 해당 기관의 평가 기록과 로그인 사용자의 시설 권한을 확인한 후 제공합니다. 공용 폴더에 있다고 다른 기관 사진을 열 수는 없습니다. 기존 사진은 이동하지 않습니다.

## 실제 연결 검증과 관리 열 준비

명령은 `kywa-next`에서 실행하며 JSON은 로컬 `.env` 또는 프로세스 환경에만 넣습니다. 키 파일을 GitHub·소스 ZIP에 넣지 마세요.

```powershell
# 실제 조회·권한·헤더 검사. 쓰기 없음.
python -m backend.check_connections --all
# 시험 탭·JPEG 생성, 재조회, 시험 탭 삭제·사진 휴지통 이동
python -m backend.check_connections --all --probe
# 실제 헤더 미리보기와 기존 행 해석 검사
python -m backend.migrate --organization khidi
# local-data/migration-backups에 백업 후 누락 관리 헤더만 추가
python -m backend.migrate --organization khidi --apply
# 실제 API 흐름을 임시 Google 탭에서 검증. AI 응답은 가상.
python -m backend.verify_workflow --organization khidi --run
```

`--organization`을 지정하면 그 기관 JSON의 저장 대상을 사용합니다. 미리보기/적용은 서비스 계정과 대상을 엄격하게 대조합니다. 알 수 없는 헤더·중복 의미 열·헤더 없는 사용 열·잘못된 날짜·부분 관리 정보가 있으면 변경을 중단합니다. 기존 평가 탭이 없으면 새 평가 탭을 임의로 만들지 않습니다.

`migrate --apply`는 기존 데이터 행을 일괄 변환하지 않습니다. 백업 후 다시 읽어 기존 내용이 유지되는지 확인하고 헤더 뒤에 필요한 셀만 씁니다. 조치이력 탭이 없으면 생성합니다. 이후 기존 Streamlit의 제출을 계속 받을 수 있습니다. 롤백 때도 새 앱만 중지하고 원본에 추가된 행과 관리 열을 지우지 마세요.

권한 표시, 쓰기 시험 통과, 앱 흐름 시험 통과는 각각 구분합니다. `verify_workflow`는 실제 Google API에서 두 쓰기 방식·재시도·개선조치·사진·보고서를 확인하지만 기존 Streamlit 웹 화면의 클릭이나 실제 AI 호출을 검증한 것은 아닙니다. 시험 사진의 휴지통 이동 권한도 없으면 `cleanup_needed`를 출력합니다.

회사 PC에서 인증서 오류가 나면 승인된 Windows 신뢰 저장소의 CA 묶음을 `SSL_CERT_FILE`로 지정할 수 있습니다. TLS 검증을 끄지 않습니다. Render에는 이 로컬 인증서 파일을 배포하지 않습니다.

## 배포 전 검증

백엔드 회귀검사, 이름 변환 단위검사와 프런트 빌드를 실행합니다. PC·모바일 화면 검사는 `deploy/ci.yml`에 7개 기관의 테마·버튼 상태·줄 넘침·이름 입력 시험으로 포함합니다. 로컬 브라우저 접근이 차단되면 승인된 GitHub Actions에서 실행하고 결과를 확인한 뒤 배포합니다. CI 파일 준비만으로 화면 검증 완료로 표시하지 않습니다.

## 2026-10-29 실제 Google 검증 기록

지정 서비스 계정으로 7개 기관의 조회·편집과 사진 업로드·재조회를 통과했습니다. 임시 Google 탭에서 새 앱 API와 Streamlit의 기존 append 방식 동시 제출, 중복 재시도, 기존 행 개선조치, 변환 성명, Excel·PDF를 검증했습니다. 시험 탭은 삭제하고 시험 사진은 휴지통으로 옮겼습니다. AI 응답은 가상이며 기존 Streamlit 웹 화면 자체를 조작한 검사는 아닙니다.

7개 기존 평가 탭에 필요한 관리 헤더와 조치이력 탭을 준비했습니다. 원본 600건(KYWA 134, FOWI 131, KNPS 93, KNF 13, KOHI 125, KHIDI 98, CAYF 6)은 백업과 일치합니다. KYWA는 소유자가 1행 보호를 해제한 후 S:X를 추가했습니다. 완료 후 1행 보호를 다시 설정할 수 있습니다.

업무 데이터 백업은 로컬 `local-data/migration-backups`에만 있습니다. 인증정보와 백업은 소스 패키지·GitHub에 포함하지 않습니다. 이번 검사 상태는 로컬 `artifacts/institution-verification.json`에 기록합니다. 현재 배포 사이트의 적용 여부는 배포된 커밋을 별도로 확인해야 합니다.


## AYF 추가 설정 (2026-10-29)

안양시청소년재단은 `ORGANIZATION_ID=ayf`를 사용합니다. 주소는 `https://ayf-safety.onrender.com`이며 시설 12개, 소속팀 12개를 적용했습니다. 중복된 활동사업팀은 첫 항목만 남겼으며 시설명은 제공된 표기(평청청소년문화의집 포함)를 유지했습니다. 성명은 필수 초성 변환이며 5×4 점수표의 15점은 높음입니다. 기관 색상·로고는 미제공이므로 중립 회색과 기관명을 사용합니다.

사진 폴더는 KYWA의 기존 폴더를 공유합니다. 시트는 추후 제공 예정이므로 `APP_ENV=setup`으로 운영합니다. 실제 AI 분석과 KOSHA 검색은 가능하지만 제출·개선조치·보고서 저장 API는 서버에서 차단합니다. 다른 기관의 시트로 대신 저장하지 않습니다. 시트 ID를 받으면 AYF 설정에 등록하고 헤더·권한 확인 및 백업 후 `production`으로 전환합니다.

Render의 `kywa-safety-shared-integrations` 환경변수 그룹에는 기존 서비스 계정·AI 키·KOSHA 키·AI 모델·관리자 PIN 해시만 보관합니다. 신규 기관 서비스는 이 그룹을 참조하고, 기관 ID·사이트 주소·세션 키는 서비스별로 분리합니다. 기본 관리자 PIN은 기존 운영 방침의 초기값을 사용합니다. 인증값을 GitHub에 저장하지 않습니다.
