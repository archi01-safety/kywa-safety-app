# AYF 시설 중심 운영 전환

AYF는 `department_enabled=false`, 성명 `disabled`다. 시설 11개를 선택하고 사진/설명을 제출한다. 다른 기관의 필수 부서·초성 성명 규칙은 유지한다.

평가표는 A:Q 17열이다. 기존 C열 담당 부서와 S열 제출자 성명을 삭제한다. 내부 행 식별·중복 처리·조치 이력은 19칸 canonical 구조를 유지하고 두 항목을 빈 값으로 매핑한다. 기존 19열도 전환 중 읽기·쓰기를 지원한다. Excel/PDF/HWPX 및 관리자 필터/상세에서 부서·성명을 제외한다.

## 전환 절차

1. 비공개 공유 드라이브 사본에서 `backend.migrate_ayf.migrate(settings, apply=True)`와 제출/재시도/삭제/직접 수정 검사를 수행한다.
2. 검증 커밋과 CI를 확정한다. 운영 앱의 관리자 storage-maintenance API로 쓰기를 중지한다.
3. 운영 파일 전체를 비공개 공유 드라이브에 복사하고 local-data에 전체 Google grid 스냅샷을 남긴다. 인증 JSON/업무 데이터를 공개 저장소에 넣지 않는다.
4. migrate는 평가 탭의 숨김 백업, 관리 원본 연결값 정규화, 두 열 삭제를 원자적 batchUpdate로 처리한다. 진행 중인 제출 메모/요청은 거부한다. 기존 행 메타데이터와 나머지 값이 같은지 확인한다.
5. 호환 코드를 배포한다. 이번 작업은 사용자 요청에 따라 배포 후 별도 업무 시험을 하지 않는다.

## 복구

17열 상태에서 19열만 지원하는 구버전 코드로 단독 롤백하지 않는다. 쓰기를 멈추고 이관 후 새 기록을 별도로 백업한 뒤 전체 파일 백업 또는 숨김 평가 탭과 관리 탭 스냅샷을 함께 복원한다. 행 메타데이터·요청 기록·조치이력을 함께 대조한다. 새 기록을 덮어쓰지 않는다. 이미 17열이면 이관 재실행은 삭제를 반복하지 않는다.

## PIN 설정

KYWA의 공유 환경 그룹은 유지한다. 나머지 7개 서비스에서 개별 ADMIN_PIN_HASH를 추가해 공유값을 override한다. 원문/해시는 공개 문서·소스·ZIP에 포함하지 않는다. 환경변수는 Save only 후 검증 SHA 배포 시 반영한다.
