# 기관별 버전과 복구

최신 배포는 `HANDOFF.md` → `artifacts/render-deployments.json` → 해당 기관의 JSON 순서로 확인합니다. 동일한 공통 소스라도 기관마다 실제 배포와 시트 구조가 다를 수 있으므로 기관 태그를 사용합니다.

- `kywa/v1.0.0`, `ayf/v1.0.0` 등: 2026-11-10 운영 기준 `b180b29`.
- `<기관>/v1.1.2`: 복수 사진·법령·세션·정렬 보완 소스 `329f2f8`. JSON의 `state: deployed`와 Render 배포 기록을 함께 확인합니다.
- KYWA·AYF의 v1.1.0, KYWA·AYF·FoWI의 v1.1.1은 순차 배포 중 실제 사용된 중간 버전입니다. 같은 버전의 소스를 나중 커밋으로 덮어쓰지 않습니다.

“AYF를 v1.0.0으로 복구”처럼 기관과 버전을 지정합니다. “v3.2”처럼 등록된 패치 버전이나 기관이 불명확하면 대상을 확인합니다. 인증값·업무 백업은 이 폴더에 보관하지 않습니다.

v1.2.0은 개선조치 작업 화면·모바일 헤더·focus 갱신 보완이며 시트 구조/평가 기준은 v1.1.2와 같다. Actions는 저장소 설정에서 중지했다. 이전 태그 복구 시에도 워크플로 YAML을 되살리거나 Actions를 활성화하지 않는다. 기존 실행 로그는 역사 기록이며 원격 산출물은 사용자 요청으로 삭제했다.

## 복구 순서

1. 해당 JSON과 태그의 소스 일치를 `python scripts/release_registry.py verify --organization ayf --version v1.0.0`으로 확인합니다.
2. 현재 운영 파일 전체와 GridData·행 식별·숨김 관리·조치이력을 비공개로 다시 백업합니다. 신규 앱 쓰기를 잠시 점검 상태로 전환합니다.
3. 현재/대상 시트 구조를 비교합니다. v1.1 사진 열을 모르는 버전으로 돌아갈 때는 `python -m backend.rollback_photo_schema`로 계획을 확인하고 승인된 대상의 `--apply`를 실행합니다. 새 사진·계획은 숨김 복구 정보에 보관합니다. **복구 이후 제출된 평가도 보존합니다.**
4. 다른 기관의 서비스나 공유 인증 그룹은 바꾸지 않고 대상 서비스만 검증 태그의 실제 SHA로 배포합니다. 시트 구조가 다른데 코드만 먼저 되돌리지 않습니다.
5. 신규 제출·같은 요청 재시도·조회·사진·조치 이력·출력을 확인하고 쓰기 점검을 해제합니다. 결과를 해당 기관의 새 배포 이력과 HANDOFF.md에 기록합니다.
6. 상위 버전으로 돌아오면 사진 열을 확장한 뒤 보관 정보와 현재 수정 버전을 대조해 복원합니다. 사용자가 이후 수정한 내용을 무조건 덮어쓰지 않습니다.

v1.1.2의 가운데 정렬만 되돌리려면 최신 백업의 가로 정렬 항목만 대상 셀에 복구합니다. 값·사진 링크·다른 서식과 신규 제출을 전체 파일의 과거 사본으로 덮어쓰지 않습니다.

내부 세부 판정은 담당자/사진 각도 대조 전까지 비활성입니다. 기능이 구현됐거나 반복 점수가 같다는 이유만으로 활성화하지 않습니다. 자세한 범위와 검증 한계는 PHOTO-REVIEW-V1.1.ko.md를 따릅니다.
