## 2026-11-13 — v1.1 구현·검증 중, 운영 배포 전

현재 작업은 `feature/photo-review-v1.1` 브랜치, `kywa-v1.1/kywa-next` 작업 폴더에 있다. 기준 운영 소스는 아래 2026-11-10의 `b180b29`다. 복수 사진(최초 최대 2장/개선 후 1장), 기존 박스 드래그 앤 드롭, 조치예정, 법령 링크, 오류 종류/요청번호, 지연 조회·사진 로딩 안내와 세션 보완을 구현 중이다. 운영 시트의 추가 사진 열 이관이나 새 코드 배포는 아직 수행하지 않았다. 기존 운영 시트는 KYWA 등 19열, AYF 17열이다.

AYF 운영 브라우저 접근 제한은 사용자가 사이트 권한을 변경한 뒤 새 연결에서 해제됐다. 관리자 로그인·필터·상세 사진·텍스트 분석·명시적 시험 1건 제출·재평가/조치 중 저장을 수행했다. 이 구간에서 원래의 503 오류는 재현하지 못했다. 시험 행만 전체 파일 비공개 백업 후 제거했고 기존 평가 8건의 값 보존을 대조했다. 비공개 근거는 `local-data/v11-live-baseline/`에 있으며 공개 저장소에 업로드하지 않는다. 전체 벽시계 구간에는 도구 대기 시간이 포함되므로 이를 정확히 7분의 능동 시험이라고 기록하지 않는다. 보고서 다운로드 UI는 조작했으나 실제 저장 파일의 대조를 완료했다고 표시하지 않는다.

추가 사용자 신고 시 AYF 화면에서는 로그인 만료를 확인했다. Render 로그에는 09:48 종료 후 10:10 재시작이 있으며, 기존 메모리 전용 PIN 세션이 서버 재시작 때 소실되는 구조를 확인했다. 새 구현은 기관/PIN 설정에 묶인 토큰 해시와 절대 만료 시각을 숨김 관리 탭에 보관한다. 한 프로세스/한 인스턴스 운영을 유지하고, 유효 로그인 1시간·명시적 연장·로그아웃 폐기를 보존한다. 이 변경 배포 후 구방식 로그인은 한 번 다시 필요하다. 기존 인증정보나 PIN을 변경하지 않는다.

로컬 백엔드 회귀검사 313개·프런트 단위검사 15개·TypeScript·Next.js webpack 빌드를 통과했다. 이 작업 폴더의 node_modules는 기존 설치의 정션이므로 Turbopack의 프로젝트 밖 파일 제한이 있고, 로컬 빌드는 webpack으로 수행했다. [초안 PR #5](https://github.com/archi01-safety/kywa-safety-app/pull/5)의 c541315에 대한 [CI 43354042458](https://github.com/archi01-safety/kywa-safety-app/actions/runs/43354042458)는 백엔드·정상 npm ci/기본 빌드·PC/모바일·8개 기관·root/AX Docker 검사를 통과했다. 이후 법령명 파서·화면 조회 재사용 보완의 최종 CI는 별도로 확인한다. 실제 한글 편집·출력은 앱 접근 미승인으로 수행하지 못했으며 사용자에게 설정 → Computer use → Any App 및 앱 접근 시 Always allow 경로를 안내했다. 운영 이관, 수정 후 AYF 7분 시험과 8개 기관 배포도 남아 있다.

8개 기관의 기존 비공개 검증 폴더에서 각각 별도 파일 사본으로 오른쪽 사진 열 확장·재실행·기존 기록 보존·최초 2장/개선 1장 실제 Drive 저장/재조회·중복 재시도·계획 저장·재시작 인증·Excel/PDF/HWPX 3장 출력·삭제 후 제출·구버전 구조로 복구 시 신규 기록 보존을 통과했다. 보존 건수는 KYWA 134, AYF 8, FoWI 131, KHIDI 98, KNPS 187, KNF 13, KOHI 125, CAYF 7이다. 운영 원본에는 쓰지 않았고 시험 파일·사진만 휴지통으로 정리했다. 사본의 native table과 basicFilter가 공존할 때 사진 열 확장 요청이 충돌하는 경우를 발견해 표가 필터를 관리하도록 수정했다. 비공개 결과와 출력은 local-data/v11-google/에 있다.

## 새 PC와 이동 전 백업

새 PC 실행 절차는 SETUP.md를 따른다. GitHub에는 소스·설명서·검증 요약을 보관한다. 인증정보와 실제 데이터는 접근이 제한된 별도 저장소로 이전한다. 기존 PC의 `secret`, `local-data` 및 업무 보고서는 공개 저장소에 포함하지 않는다.

이동 직전에는 당시 HEAD·배포 커밋·시트 구조·남은 작업을 다시 확정하고 소스 패키지 해시와 비공개 백업 목록을 기록한다. 지금은 최종 이동 백업을 수행하지 않는다. 대화 전문 대신 결정 이유·검증 근거·미완료 사항을 유지한다.
