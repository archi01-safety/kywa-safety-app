## 4. 서비스 구조와 실행 파일

현재의 `app.py`는 Streamlit 업무 코드가 아니라 **FastAPI 실행 진입점**이다.

```text
브라우저
  → Render: Next.js 정적 화면 + FastAPI API (같은 origin)
  → Gemini: 얼굴/위험 관찰·보고서 문장 생성
  → Google Sheets: 평가·조치·관리 정보
  → Google Drive: 처리된 사진
  → KOSHA API: 기술지침 조회 / 법제처 API: 현행 법령 검증·원문 링크
```

- 프런트: Next.js/React/TypeScript. 빌드 결과는 `frontend/out/`에 정적 export한다. 운영에서 Next.js 서버를 별도로 실행하지 않는다.
- 백엔드: Python/FastAPI. `backend/main.py`가 API·인증·흐름을 연결한다.
- Render: `kywa-next/Dockerfile`의 Node 빌드 단계와 Python 실행 단계. 일반 운영 접두 경로는 빈 문자열, 컨테이너 `HOST=0.0.0.0`, 기본 `PORT=10000`, 상태 점검 `/healthz`.
- 공통 실행: `python app.py`. 로컬 기본 HOST는127.0.0.1/PORT8000이며 운영에서는 플랫폼 설정을 사용한다.
- `APP_ENV=demo`는 합성 AI·로컬 자료다. 실제 Google/AI 연동 성공을 의미하지 않는다. 운영8개와 준비 모드를 혼동하지 않는다.
- 사진 초안·관찰 캐시·보고서 작업은 여전히 프로세스 메모리를 사용한다. **단일 worker/인스턴스** 구조다. 서버리스로 단순 이동하거나 worker 수를 늘리면 이어지는 작업이 깨질 수 있다.
- PIN 세션은 별도로 숨김 관리 저장소를 사용해 유효한 세션의 서버 재시작 복원을 지원한다. 모든 메모리 초안/작업까지 복원된다는 뜻은 아니다.

예전 Streamlit 원본은 별도 저장소 `archi01-safety/kywa-ai-risk-assessment`의 기관 브랜치를 참고한 것이다. 현재는 Streamlit 운영을 종료했지만 기존 행 형식과 행 추가 호환은 유지한다. 원본 `app.py`를 현재 실행 파일 위에 덮어쓰지 않는다.

## 6. 현재 사용자 흐름과 디자인 원칙

1. **AI 위험성평가**: 시설/부서/성명(기관 설정에 따름), 사진0~2장 또는 설명을 입력한다.
2. 분석 버튼 → 얼굴 탐지·처리 → 위험 관찰/서버 판정·법령 검증 → 처리 사진과 결과를 보여준다.
3. 결과의 장소·위험상황·감소대책·빈도·강도를 검토/편집하고 항목을 골라 안전센터 DB로 전송한다. 선택 질문 미응답도 제출 가능하다.
4. **개선조치·재평가**: 관리자 로그인 → 목록/필터/원본 조회 → 조치계획 또는 실제 조치·개선 후 사진1장 → 재평가·검토·저장한다.
5. **결과보고서**: 시설/기간/상태 등으로 조회 → Excel/PDF/HWPX 생성·다운로드한다. 최신 시트 상태를 검사한다.

- 화면 상태는 내부적으로 `접수 / 조치예정 / 조치 중 / 완료`, 화면 표시는 `접수 / 조치예정 / 조치중 / 조치완료`다. 계획은 재평가 없이 저장할 수 있고 완료는 담당자 확인으로 처리한다.
- 차콜 기반 다크 디자인과 라이트 전환을 유지한다. 기관 포인트와 빨강/노랑/초록 위험·경고·성공 의미 색상은 구분한다. 출력 문서는 흰색이다.
- KYWA 헤더는 로고와 어울리는 **흰색**이며, 우측 상단의 장식 곡선·그라데이션은 제거했다. 분석 버튼은 기존 전체 너비형이다. 재평가 버튼은 기관 포인트로 강조한다.
- 지원기관은 해당 기관 × 한국청소년활동진흥원 표시, 기술지원 안내, Powered by KYWA 푸터와 개발자정보 팝업을 사용한다. 모바일 헤더는68px/PC76px로 컴팩트하게 유지한다.
- 다음에 할 작업 하나를 얇은 포인트 테두리/은은한 빛으로 강조한다. 연속 점멸과 과도한 네온을 사용하지 않는다.
- 공통 진행 팝업은 실제 단계, 성공/오류, 재시도 동작을 보여준다. 임의의 진행률이나 실제 저장을 단정하는 다운로드 완료 문구는 쓰지 않는다. 진동은 지원 기기의 `navigator.vibrate`만 사용한다.
- 로고는 홈이다. 현장 입력·성명·사진·분석/재평가 초안·필터·중복 요청 캐시와 서버 임시 초안을 초기화한다. 관리자 로그인·테마는 유지하고, 저장 중에는 초기화를 잠시 막으며 늦은 응답이 복원하지 않게 한다.
- 개선조치 화면의 목록·원본·작성 영역은 넓은 화면에서 독립 스크롤한다. 선택 요약 고정/작은 화면 원본 보기를 유지하고 화면 리사이즈만으로 목록을 다시 불러오지 않는다.
- 사용자는 API 공급자명을 화면에서 고지하지 않기로 했다. 기술 문서에는 실제 공급자를 기록하되 제품 안내에 임의로 추가하지 않는다. API 학습 미사용 안내는 사용자가 유료·옵트아웃 적용을 확인한 범위에 근거한다.

## 7. 개인정보와 사진 처리

### 성명

성명은 브라우저 메모리에서 `홍길동 → 홍㉠㉢`으로 변환하고 실시간 미리보기를 제공한다. 첫 글자만 보존하며 두 번째 이후 모든 글자는 초성으로 변환한다. 복성도 첫 글자 규칙을 적용하고 쌍초성은 대응 문자로 표시한다. 한글 정규화·공백 제거·최대100글자·완성형 한글 검증과 조합 입력 처리를 유지한다.

분석/재평가에는 이름 필드를 보내지 않는다. 제출에는 변환값만 넣고 서버도 변환 형식만 허용한다. 원본을 URL·로그·브라우저 저장소에 기록하지 않고 성공 시 입력을 비운다. 기존 원본 이름은 조회 경계에서 변환한다. **이름 입력란에 대한 보호이며 사진·자유 설명의 이름까지 자동 제거한다는 보장은 아니다.** AYF에는 성명 입력 자체가 없다.

### 사진

- 기존 사진 박스에서 선택·촬영·드래그 앤 드롭·추가·교체·개별 삭제·대표사진 순서 변경을 지원한다. 최초 최대2장, 개선 후 최대1장이다.
- 확장자/MIME만 보지 않고 실제 형식을 판독한다. JPEG/JPG, PNG, WebP, HEIC/HEIF와 MPO로 판독되는 JPEG의 대표 정지사진을 처리한다. `.jpg`인데 실제WebP인 사례와 iPhone JPEG/MPO 문제를 해결했다. Live Photo 동영상 처리 기능은 아니다.
- 각20MB/5,000만 화소 한도, EXIF 방향 보정·RGB·메타데이터 제거·긴 변1600px 이하 정규화. HEIF 변환은 libvips/libheif 환경을 사용한다.
- 업로드는 정규화/미리보기 단계다. **분석 때** AI 머리 영역 탐지 → 최소 여유 타원형 강한 가우시안 블러 → 처리 사진+설명으로 위험 분석한다. 현재 경로를 OpenCV 사각 모자이크로 되돌리지 않는다.
- 탐지 오류/시간 초과/잘못된 좌표이면 미처리 사진으로 진행하지 않는다. 정상적으로 얼굴 없음이 확인된 경우만 그대로 사용한다.
- 분석 전 체크박스는 없고 처리 후 사진별 개인정보 확인은 기본 체크 상태다. 해제하면 제출을 막되 다시 체크했다고 재분석시키지 않는다. 기본 체크를 수동 확인 이력으로 기록하지 않는다.
- 좌우90도 회전은 정규화 기초 사진과 누적 각도에서 새 사진 ID를 만든다. CSRF·세션 소유권·동일 요청 재시도를 검증하고 실패 시 기존 사진을 유지한다. **분석 뒤 회전하면 초안을 무효화하고 재블러/재분석한다.**
- 미리보기·분석·Drive·세 출력물이 같은 처리 사진/방향을 사용한다. 기존 Drive 파일은 일괄 변경하지 않는다.

새 사진명은 한국 저장 요청 시각 기준 `우주_20261116_094655.jpg`, 개선 후 `우주_개선후_20261116_103020.jpg` 형태다. 중복 판단은 파일명이 아닌 기관ID/요청ID 내부 속성을 사용한다. Drive의 공식 `webViewLink`를 저장하고 권한을 인터넷 전체 공개로 바꾸지 않는다.

## 8. Google 저장 구조·직접 편집·성능

- 평가표는 실제 사람이 읽는 열만 유지한다. `평가ID·평가기준버전·처리상태·수정버전·시스템데이터`는 같은 파일의 숨김 `_시스템관리`에 있다. `조치이력`도 보존한다. 숨김은 접근 제어의 대체 수단이 아니다.
- 일반20열/AYF18열의 **오른쪽 끝은 개선 전 사진2 링크**다. 기존 사진 기록은 첫 사진이다. 관리 열을 공개 평가표에 다시 추가하지 않는다.
- 기관별 열 매핑을 사용한다. A:R/S 같은 KYWA 위치를 AYF/KHIDI에 강제하지 않는다. 기존 데이터/헤더와 충돌하면 확장을 중단한다.
- 행 DeveloperMetadata `kywa.assessment.id`가 불변 평가 ID를 연결한다. 행 번호만으로 평가/조치를 찾지 않는다.
- 행 삭제/행 전체 값 지우기는 삭제 상태로 보관한다. 목록·통계·보고서에서 제외하며 사진·이력은 복구용으로 보존한다. 같은 내용의 별도 제출은 합치지 않는다.
- 신규 제출은 `appendCells`로 마지막 데이터 행 다음에 쌓인다. 요청 영수증과 행 추가를 원자적으로 기록하고 실제 추가 위치를 연결한다. 응답 유실 후에는 해당 요청 기록을 먼저 확인해 중복 추가를 막는다. 관리자가 삭제한 제출을 재시도로 되살리지 않는다.
- 시트 위험상황/감소대책/수치 수정은 동기화한다. 수치 변경은 저장된 기준의 빈도×강도/등급으로 정리한다. 기준을 모르는 기록은 확인 대상으로 분리하고 과거 전체를 현재 기준으로 재계산하지 않는다.
- 잘못된 행은 그 행만 ‘확인 필요’로 분리한다. 다른 신규 제출·조회는 허용하되 문제가 포함된 보고서를 조용히 누락 생성하지 않는다. 앱 초안을 작성 중 시트가 바뀌면 내용을 보존하고 해당 건 재확인을 요구한다.
- 일부 열만 정렬/다른 평가에 셀 끼워넣기는 지원하지 않는다. 평가표·행 식별·숨김 관리·조치이력은 같은 시점 묶음으로 복구해야 한다.
- 신규/기존 서식은 Roboto10pt·열별 정렬/줄바꿈/테두리·Google 표 범위를 보존한다. 시간대는 Asia/Seoul, 타임스탬프는 ISO 문자열이 아닌 실제 날짜값/한국 표시 형식이다.
- 빈도·강도·점수·등급·상태 등 단답형은 가운데, 긴 문장은 왼쪽/줄바꿈이다. Google native table 자동 확장이 서식을 덮어쓰는 문제도 저장 후 확정 처리한다.

성능 개선은 Vercel 이전 대신 **현재 Render에 반영**했다. 시트/행 식별/관리 정보를 묶어 읽고 같은 조회의 중복 작업을 줄인다. 서버의 완료된 평가 스냅샷을 오래 보관하지 않고 요청 내/진행 중 조회만 재사용한다. 인증 목록은 브라우저 메모리에서 권한·세션·필터/버전별30초, 공개 집계는 서버30초/연도별 최근 성공 자료를 사용한다.

현장 입력 탭에서는 관리자 목록을 불러오지 않는다. 저장/삭제/수동 갱신/필요한 탭 복귀는 갱신하고 보고서 생성·다운로드는 최신 상태를 검사한다. 연속 필터는 이전 요청을 취소하고 최신 응답만 반영한다. 느린 조회는 진행 팝업, 사진은 로딩/없음/실패·재시도 안내를 제공한다. HTML은 재확인하고 해시 정적 자산만 장기 캐시한다. 관리자 데이터·사진·다운로드를 공개 CDN에 캐시하지 않는다.

Vercel의 화면·조회/Render 시험 백엔드 구성은 별도 시험판이다. 현재8개 운영 서비스를 Vercel로 옮기거나 임시 저장소/큐를 도입하는 작업은 대기 과제로 간주하지 않는다. 무료 첫 접속 대기는 수용하며 절전 방지 예약 호출을 추가하지 않는다.

## 9. 법령·내부 판정·보고서 핵심 계약

### 법령

Gemini 제안을 공식 API가 검증한다. API가 모든 법적 적합성을 판단하거나 AI 출력 자체가 법적으로 확정되는 것은 아니다.

제시 번호가 존재하지만 제목이 다를 때, **같은 현행 시행본**에서 공백/괄호 등을 정리한 제목이 정확히 일치하는 유효 조문이 하나이면 번호를 보정한다. 예: `산업안전보건법 제37조(안전조치)` → `제38조(안전조치)`. 항·호도 존재를 확인한다. 없는/삭제 조문, 제목 미일치/중복 후보, 확인 안 되는 항호, API 장애는 해당 근거만 공식 검색 링크로 대체한다. 여러 근거는 각각 독립 처리한다.

화면/출력에는 **최종 문구·원문 링크만** 표시하고 보정 안내·배지는 표시하지 않는다. 보정 이력은 `_internal_law`로 내부 저장한다. 신규는 초안 확정 후 같은 문구를 저장하고, 기존 기록은 조회/보고서 사본만 보정하며 원본 셀을 바꾸지 않는다. `/api/law-links`는 기존 items/configured에 최종 text를 추가한 호환 응답이다. 본문/제목 색인을 재사용하고 장애가 분석 전체를 중단시키지 않게 한다.

KOSHA는 별도 기술지침 API다. 분석 결과의 키워드 추천·검색·원문 연결을 유지하고 법령과 기술지침을 같은 법적 성격으로 표시하지 않는다.

### 내부 세부 판정

- `backend/risk_profiles/<기관>.json`은 `<기관>-facts-20261116-v3` 기준이다. 현재 모든 기관 프롬프트 버전은 `<기관대문자>-PROMPT-20261116-v3`다.
- 가능성15단계 × 피해규모20단계의 내부 곱은1~300 범위다. 300개의 서로 다른 정수를 모두 쓰는 체계가 아니며 **300점을20점으로 비례 환산하지 않는다.**
- 내부 가능성3단계씩 공개 빈도1~5, 피해규모5단계씩 공개 강도1~4로 묶고 기존 기관 `policy.cells`로 최종 점수/등급을 확정한다.
- AI는 원인/피해/노출/접촉/안전조치에 관한 관찰을 추출하고 서버 규칙이 계산한다. 확인 안 되는 사실은 unknown, 적용 기본값은 내부에 따로 기록한다. 미확인 안전조치의 효과를 가정해 점수를 낮추지 않는다.
- 기본값은 일 단위 이용·부주의 시 접촉·안전조치 효과 부족·악화 상태·중상/휴업·보통 피해 범위다. 기본값이 실제 관찰 사실이라는 뜻은 아니다.
- FoWI의 측정 노출률/작업시간/소음 조건은 해당 기관에만 적용하며 실제 설명의 수치/단위를 확인한다. 경미 제한은 FoWI4점/KHIDI5점/나머지6점이지만 실제 중대 기전이 확인된 추락·감전 등을 경미 표현만으로 제한하지 않는다.
- 질문은 전체 분석당 최대2개, 선택 사항이며 ‘잘 모르겠어요’를 포함한다. 답하면 AI 재호출 없이 새 초안 ID로 계산한다. 이전 초안의 신규 전송/늦은 응답과 재시도 중복을 막고 사용자가 편집한 문구를 보존한다.
- 관찰 캐시는 세션·기관·현장·사진·모델·프롬프트·기준 버전별30분/최대64개다. `_internal_risk`의 수치·기본값·근거는 기존 숨김 구조에만 저장하고 공개 API/앱/평가표/Excel/PDF/HWPX에 노출하지 않는다.
- 기존 기록은 재계산하지 않는다. 담당자 검토표는 추후 보정 자료이며 **회신을 필수로 기다리지 않는다. 다른 기관에 작성을 요구하지 않는다.**

### 출력

Excel은 상세 원문과 실제 이미지를 담는다. 연번/수치는 정수·가운데 정렬하고 제출자 성명은 변환값, 조치시각 대신 조치일자를 쓴다. 공개PIN으로 실제 담당자 이름을 알 수 없어 처리자는 출력하지 않는다. A3·가로·보통 여백·가로1페이지/세로자동·실데이터 인쇄영역·제목 행 반복·페이지 나누기 미리보기를 유지한다. 단면/한 부씩은 프린터 설정의 영향을 받는다. 사진은 셀 내 비율 유지·중앙 배치·셀 이동/크기를 따르는 앵커를 사용한다.

PDF/HWPX는 시설 정식명칭과 연도 제목, 개요/총건수·완료·미완료/최초등급/분류 차트/총평, 본문 종료와 붙임으로 구성한다. 서버 집계를 AI가 바꾸지 못하게 검증하고 총평/요약은 같은 조회/기록 버전에서 재사용한다. 생성시각·접수시각·평가ID·제출자 성명 등 불필요한 내부 정보는 제외한다.

본문1쪽 + 붙임 최대2건/쪽. 실제 사진3장인 건만 개선 전①/②/후의3열 표이며 나머지는2열과 미등록 안내다. HWPX 본문은 일반 문단, 점수/사진은 의미 있는 표다. PDF 페이지 전체를 이미지로 붙이거나 위치 고정용 투명표로 본문을 구성하지 않는다. 검증 실패를 무시한 파일을 완료로 내려주지 않는다.

파일명은 서버 `Content-Disposition` 기준이다. 시설 조회는 `우주_위험성평가_20261116.pdf`, 전체 조회는 해당 기관 약칭 `KYWA_위험성평가_20261116.xlsx` 형태다. 전체 조회 결과에 한 시설만 있어도 기관명을 사용한다. 생성일은 한국 날짜로 고정한다.

보고서 작업은 관리자 세션 귀속·메모리30분이며 서버 재시작 시 재생성이 필요할 수 있다. 공용PIN은 특정 개인의 신원 인증이 아니므로 처리자 실명을 추정하지 않는다.

## 11. 인증·설정·패키지·복구

운영 인증은 PIN 방식이며 로그인1시간/수동연장1시간, 만료5분 전 강조, 만료 시 재로그인 안내와 작성 초안 보존을 지원한다. PIN 오류5회/15분 잠금, 서버 권한/CSRF 검증을 유지한다. `ACCESS_ACCOUNTS_JSON`의 OAuth 계정 설정과 공용PIN 실제 사용자 식별을 혼동하지 않는다. 비밀값을 바꾸면 다른 기관/세션에 영향을 줄 수 있으므로 이번 요청과 관계없이 재설정하지 않는다.

기관별 기존 Sheets/Drive는 설정에 보관한다. 일부 기관이 공유 사진 폴더를 사용하므로 ‘기관별 새 폴더’를 임의 생성/교체하지 않는다. 같은 서비스 계정의 편집 권한이 있더라도 실제 업로드/조회 성공과 구별한다. 기존 환경 그룹과 연결 범위를 필요 없이 변경하지 않는다.

새PC/재시작의 기본 설치는 [SETUP.md](SETUP.md)를 따른다. 프런트 수정 뒤 정적 화면을 재빌드해야 한다. 현재 Windows의 node_modules junction 환경에서는 `npm run build -- --webpack`을 사용했다. root와 AX 빌드의 `APP_BASE_PATH`가 서버와 일치해야 한다. localhost/127.0.0.1의origin을 섞지 않는다.

Windows 전체pytest를 한 프로세스에서 돌릴 때 파일 잠금/기술자 오류가 간헐 발생했던 이력이 있다. 최종 검증은 테스트 모듈별 독립 프로세스로 수행했다. 프런트는 `npm run test:unit`, TypeScript/정적 빌드와 필요한 화면 검사, 실제 Google 쓰기는 별도 사본에서 수행한다. API 반복 검사는 비용/쿼터를 고려하며 필요 없이 반복하지 않는다.

ZIP 고정 경로:

- `artifacts/kywa-safety-source.zip`: 소스/문서/기관 설정. 실제 인증·데이터·사진·로컬 런타임 제외.
- `artifacts/kywa-safety-ax.zip`: 평탄 소스 + `/apps/kywa-safety` 정적 화면. 실행 `python app.py`, 포트는AX할당 `PORT`, 외부 데이터 경로 사용.
- AX 해시/크기는 `artifacts/ax-package.json`, 파일별 해시는source/ax-manifest를 확인한다. 문서 변경만이면 검증된 정적 export를 재사용해 패키징할 수 있다. 실제AX 등록은 아직 수행하지 않았다.

배포는 기관별로 범위를 확정하고 검사/백업 후 해당 소스 SHA를 **개별 Render Manual Deploy**한다. Blueprint 전체 동기화나 서비스 일괄 환경 교체는 하지 않는다. Render의 빌드 성공/Live 확인과 실제 업무 제출 검증은 따로 기록한다.

복구 요청은 “AYF를 v1.2.1로”처럼 기관/등록 버전을 확인한다. 태그와 매니페스트의 소스를 검증하고 최신 운영 백업을 남긴 뒤 해당 기관만 복구한다. 스키마 차이가 있으면 호환 변환을 먼저 한다. **복구 시점 이후 신규 제출·사진·조치도 보존**하며 과거 사본으로 전체를 덮어쓰지 않는다. v1.3→v1.2.1은 같은 공개 열 구조지만 명시된 세부판정 플래그는false로 맞춘다. Actions는 계속 중지한다.

2. 이 문서와HANDOFF맨 위를 읽고 실제기관/배포버전/관련설정만 대조한다.
3. 공통8개 변경인지 특정기관 변경인지 이번 지시로 판단한다. 모호한 경우에만 확인한다. 이미 승인된 같은 작업을 반복 승인 요청으로 중단하지 않는다.
4. 사본/합성 자료로 구현·검사하고 위험한 이관/실자료 변경 전에 최신 백업과 복구 경로를 마련한다. 문서에만 적힌 미검증을 통과로 취급하지 않는다.
5. 기관별검증SHA·태그·배포/검증상태와 이 문서/HANDOFF/CHANGELOG를 같은 작업에서 갱신한다. 실행변경은SETUP/.env.example, 패키지변경은ZIP/매니페스트도 갱신한다.

다른PC이동 직전 최종 백업은 **아직 실행하지 않는다**. 사용자가 이동 직전에 요청하면 최신커밋/문서/패키지를 확정하고 인증·운영데이터·사진·환경복원정보를 별도 비공개/안전한 경로로 보관한다. `.venv/node_modules/.next`는 옮겨쓰는 대신 재설치한다.
