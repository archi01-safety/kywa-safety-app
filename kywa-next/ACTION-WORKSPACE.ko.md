# v1.2.0 개선조치 작업 화면과 Actions 종료

## 변경 원인과 동작

기존 넓은 화면은 평가 목록과 상세 내용이 같은 문서 스크롤에 묶여 있었다. 긴 조치 내용을 작성하거나 목록을 내리면 참고할 원본과 선택 항목이 화면 밖으로 이동했다.

- 화면 너비 1,001px 이상·높이 650px 이상에서는 목록/선택 원본/조치 작성 영역을 화면 높이 안에서 독립 스크롤한다. 선택 시설·장소·처리상태·최초 점수는 상단에 유지한다.
- 상세 영역이 720px 이상이면 원본과 조치를 좌우로, 그보다 좁으면 상하로 배치한다. 단순 창 크기 변경은 컴포넌트를 재생성하지 않는다.
- 모바일·높이가 낮은 창은 일반 문서 흐름을 사용하고 선택한 항목의 요약을 고정한다. `원본 보기`는 고정 헤더 높이를 고려해 원본 시작으로 이동한다.
- 각 스크롤 영역은 키보드로 초점을 옮길 수 있다. 모션 감소 설정을 따른다. 팝업 종료 시 입력창의 초점을 복원하면서 화면을 임의로 스크롤하지 않는다.
- 개선조치/보고서 메뉴 간 이동과 같은 메뉴 재클릭에서 조회 조건·선택·초안을 보존한다. 로고의 홈 초기화는 기존처럼 초안을 지운다.

기존 `focus` 이벤트가 모든 복귀에서 목록 버전을 증가시킨 것이 불필요한 재조회의 원인이었다. 크기 변경 자체에 대한 목록 조회는 필요하지 않다. 이제 실제 화면 이탈이 30초 이상인 경우에만 한 번 재확인하며, 저장/분석 중이면 완료 뒤로 미룬다. 필터 변경·수동 새로고침·제출/조치 저장 후 갱신과 최종 보고서 정합성 검사는 유지한다. 절전 방지 주기 호출은 추가하지 않는다.

지원기관 헤더는 모바일 142px에서 68px, PC 100px에서 76px로 정리했다. 두 기관명을 보존하고 모바일에서는 기관명 아래 `× 한국청소년활동진흥원`, 오른쪽에 시간/연장·테마·로그아웃·환경을 배치한다. KYWA의 기존 헤더 높이와 로고는 유지한다.

## Actions 정리

사용자의 Streamlit 종료·Actions 전체 중지 요청에 따라 다음을 수행했다.

- `kywa-safety-app`의 Actions 산출물 70개(1,476,204,019바이트)를 삭제했다. 마지막 운영 CI의 검증 ZIP 2개는 삭제 전 로컬 비공개 영역에 보관했다.
- `kywa-safety-app`, `kywa-ai-risk-assessment`의 Actions 실행을 저장소 단위로 끄고 당시 실행 중이던 작업을 취소했다. 산출물 잔여 수는 모두 0이다.
- 두 저장소 기본 main 브랜치의 워크플로 17개를 제거했다. 공통 운영 브랜치의 7개 워크플로 및 소스 패키지용 CI/상태확인 템플릿 2개도 제거한다.
- Render 설정인 `render.yaml`, `deploy/organizations.render.yml`은 유지한다. 검사 코드와 수동 실행 명령은 남긴다. 소스 ZIP에서 Actions YAML을 다시 생성하던 코드는 제거했다.
- 과거 태그/커밋과 실행 로그는 역사 기록이다. 과거 버전을 복구할 때도 Actions는 끈 상태를 유지하고 워크플로 파일을 운영 브랜치로 복원하지 않는다. 다시 활성화하려면 별도 사용자 지시가 필요하다.

비공개 증빙: `local-data/actions-retirement-20261113/`. 기본 브랜치 정리 커밋은 앱 저장소 `4159dd3`, 이전 Streamlit 저장소 `09db8bf`다. 인증정보·업무 데이터는 해당 정리에 사용하거나 공개하지 않았다.

## 검증과 한계

- 로컬 백엔드: 26개 모듈을 독립 프로세스로 실행하여 337개 통과. 같은 프로세스에서 전체 실행할 때 Windows 임시 Excel 파일의 잠금/잘못된 파일 기술자 오류가 간헐적으로 발생했으므로 성공한 검사 방식과 실패 이력을 구분한다. 백엔드 제품 코드는 이번에 바꾸지 않았다.
- 프런트 단위검사 20개, TypeScript 및 root/AX webpack 정적 빌드.
- 합성 36건으로 320/390/768/1280/1440/1920px, 목록/원본/작성 영역 독립 스크롤, 크기 변경 및 메뉴 이동 후 초안/선택 유지, 계획 저장·재평가·완료 저장을 검사했다.
- KYWA 창 크기 연속 변경 전후 `GET /api/assessments`는 1회로 동일했다. 창 크기 변경은 추가 조회를 만들지 않았다.
- 지원기관 7개 모두 320/390/768/1440px에서 이름/제어 버튼이 헤더 내부에 있고 가로 넘침이 없었다. 모바일 헤더는 68px였다. 다크/라이트를 확인했다.
- 새 Actions CI는 실행하지 않는다. 로컬 Docker 실행기는 설치되어 있지 않으며 실제 Render Docker 빌드와 Live 확인은 배포 기록으로 구분한다. 실제 AX 서버 등록은 별도 미검증이다.

시트 구조·값·사진·평가 기준·프롬프트·PIN·환경변수는 변경하지 않는다. 내부 세부 판정은 비활성 상태를 유지한다. 담당자 검토표는 KYWA 검토용이며 다른 기관에 작성을 요청하지 않는다. 기관별 기준 보정은 별도 검증 후 결정한다.
