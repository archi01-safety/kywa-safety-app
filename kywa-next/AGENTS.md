# 작업 및 인수인계 규칙

- 작업 시작 시 HANDOFF.md → SETUP.md → 최근 CHANGELOG.md 순서로 읽는다. 실제 GitHub 브랜치, Render 배포 커밋, Google 시트 헤더를 문서와 대조한다.
- 기능·운영 데이터·배포·검증 상태가 바뀌면 같은 작업에서 HANDOFF.md와 CHANGELOG.md를 갱신한다. 실행 방법이 바뀌면 SETUP.md와 .env.example도 갱신한다.
- 구현 완료, 로컬 검사, CI 통과, 실제 배포, 운영 검증을 구분한다. 미검증 항목을 완료로 표시하지 않는다. 이전 대화가 새 PC에 자동 전달된다고 가정하지 않는다.
- AYF 연결·7개 지원기관 배포는 완료했다. 후속 승인 범위는 AX 호환 소스·등록 ZIP 작성이며 AX 서버/Apache/systemd 및 기존 Render 서비스는 변경하지 않는다. 그 다음 사용자 지정 7개 기관 메인·서브 컬러를 적용한다. KYWA 운영 서비스와 핑크 테마는 유지한다.
- 운영 시트 변경 전 사본 검사·최신 백업·쓰기 점검을 수행한다. 숨김 관리 탭에는 중복 방지와 이력 연결 정보가 있으므로 임의 삭제하지 않는다.
- 인증 JSON, API 키, PIN/해시, 세션 비밀값, 실제 제출 기록·사진·보고서·전체 기술이관 ZIP은 공개 GitHub에 올리지 않는다. 문서에는 비밀값 대신 환경변수 이름과 준비 절차만 기록한다.
- 다른 PC로 이동하기 직전 사용자가 요청하면 최신 소스와 문서를 확정하고 비공개 데이터·인증정보를 별도 백업한다. 현재는 이동 전 최종 백업을 실행하지 않는다.
- 사용자 지시와 이미 받은 권한을 확인하여 불필요하게 재승인을 요청하지 않는다. 실제 도구 제한과 사용자 승인 부족을 혼동하지 않는다.
