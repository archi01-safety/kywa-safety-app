# 작업 및 인수인계 규칙

- 새 작업은 PROJECT-CONTEXT.ko.md의1~5절과 HANDOFF.md 맨 위를 먼저 확인한다. SETUP.md·최근 CHANGELOG.md·컨텍스트의 관련 전문 절만 추가로 읽는다. 과거 전체 대화/이력/실자료를 매번 로드하지 않는다. 사용자 최신 지시와 실제 코드/배포 근거를 우선한다.
- 현재 공통 운영은8개 기관v1.3.0, 실제 SHA는 artifacts/render-deployments.json과 releases/<기관>/에 있다. 문서 HEAD와 배포 SHA를 구분한다. 로컬 kywa-v1.1은 폴더명이며 최신 소스 작업tree다. 다른 worktree의 브랜치를 강제로 이동하지 않고 최신 origin/codex/kywa-next에서 작업 브랜치를 만든다.
- 기능·운영·검증 상태가 바뀌면 같은 작업에서 PROJECT-CONTEXT.ko.md의 현재 상태와 HANDOFF.md/CHANGELOG.md를 갱신한다. 재개 시작문은 현재 핵심 조건이 바뀔 때 갱신한다. 실행 변경은 SETUP/.env.example, 배포는 기관별 버전/태그/복구 기록, 패키지는 ZIP/매니페스트에도 반영한다.
- 구현·로컬 검사·과거CI·실제 배포·운영 업무 검증을 구분한다. 미검증을 완료로 쓰지 않는다. 문서만 바꾸는 작업은 앱 전체 검사/배포를 반복하지 않는다. 새 PC에 이전 대화나 비공개 자료가 자동 전달된다고 가정하지 않는다.
- 일반 공개 시트20열/AYF18열이다. AYF는 부서·성명을 수집하지 않는다. 기관별 공개 평가표·시설/부서·성명·색상을 유지하고 KYWA 규칙을 다른 기관에 강제하지 않는다. 관리 열/숨김 탭·행 메타데이터는 중복 방지·조치 이력 연결에 필요하므로 임의 삭제하지 않는다.
- 운영 시트/구조 변경은 필요한 범위의 실제 헤더 대조, 사본 검사·최신 값/서식/행 식별/숨김 관리/조치이력 백업·쓰기 점검을 거친다. 새 PC 설치/소스 복제만으로 이관을 반복하지 않는다. 복구 이후 신규 제출·사진·조치를 보존하고 과거 파일로 통째로 덮어쓰지 않는다.
- v1.3 기관별 내부 판정은 검증 후 기본 활성화다. DETAILED_RISK_ENABLED=false는 기존 판정 복구 설정이다. 담당자 검토표 회신은 필수 조건이 아니고 다른 기관에 작성을 요구하지 않는다. 합성 기준/반복/구도 검사를 실제 전문가·실사 정확도 인증으로 표현하지 않는다. 과거 기록은 재계산하지 않는다.
- GitHub Actions는 사용자 요청으로 두 저장소 모두 중지했다. 새 PC·검증·복구를 이유로 재활성화하거나 .github/workflows YAML을 만들지 않는다. Render 설정 YAML은 Actions와 구별한다. 무료 독립 서비스·첫 접속 대기 수용 방침을 유지하며 절전 방지 예약 호출을 추가하지 않는다.
- 인증 JSON·API 키·PIN/해시·세션 키·실제 제출기록/사진/보고서·업무 백업·전체 기술이관 원본ZIP은 공개 GitHub/로그/채팅에 넣지 않는다. 문서에는 환경변수 이름·경로·절차만 쓴다. 기존 인증/공유 그룹을 불필요하게 바꾸지 않는다.
- AX ZIP은 외부 비공개 설정을 읽는 계약을 유지한다. 기본 /var/lib/ax-apps/kywa-safety/ax.env 또는 APP_ENV_FILE은 소스 밖에 두며 업데이트 때 보존한다. AX marker/ASGI app:app·production 기본값·의존성3.11 호환·API/Google 연결·기관별 아이콘을 패키지 검사한다. 실제 서버 연동은 PC 점검과 구분하고 인증정보를 ZIP에 넣어 해결하지 않는다. AX-DEPLOYMENT/AX-VERIFICATION의 미완료 항목을 먼저 확인한다.
- 실제 Git/브라우저/앱 접근 제한과 사용자 승인 부족을 혼동하지 않는다. 최신 지시와 이미 받은 권한을 활용해 불필요한 재승인을 요청하지 않고, 반드시 필요한 사용자 조치/미검증은 정확히 설명한다. 제품 UI에 API 공급자명 등 불필요한 내부 구현 정보를 추가하지 않는다.
- 다른 PC 이동 직전 최종 비공개 백업은 사용자가 그 시점에 요청하면 수행한다. 현재 컨텍스트 정리만으로 이동용 인증/운영데이터 백업을 시작하지 않는다. 사용자가 직접 삭제하기로 한 IMG_9084.JPEG는 추가 삭제/이동하지 않는다.
