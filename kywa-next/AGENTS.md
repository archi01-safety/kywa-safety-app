# 작업 및 인수인계 규칙

- 작업 시작 시 HANDOFF.md → SETUP.md → 최근 CHANGELOG.md 순서로 읽는다. 실제 GitHub 브랜치, Render 배포 커밋, Google 시트 헤더를 문서와 대조한다.
- 기능·운영 데이터·배포·검증 상태가 바뀌면 같은 작업에서 HANDOFF.md와 CHANGELOG.md를 갱신한다. 실행 방법이 바뀌면 SETUP.md와 .env.example도 갱신한다.
- 구현 완료, 로컬 검사, CI 통과, 실제 배포, 운영 검증을 구분한다. 미검증 항목을 완료로 표시하지 않는다. 이전 대화가 새 PC에 자동 전달된다고 가정하지 않는다.
- 2026-11-10의 기준 운영 소스는 b180b29a5f9cdd39b30aa7d51e06c67584fb29cf다. 2026-11-13에는 v1.1 사진·상태·법령·세션·정렬 개선을 순차 검증·배포한다. 기관별 실제 Live SHA와 시트 20열/AYF 18열 적용 여부는 HANDOFF.md 맨 위, artifacts/render-deployments.json, releases/<기관>/ 매니페스트를 대조한다. 기관별 평가 기준·색상·성명/부서 설정은 유지한다. 내부 세부 판정은 전문가·사진 각도 대조 전까지 DETAILED_RISK_ENABLED=false를 유지하며 활성화 완료로 표시하지 않는다. 실제 AX 등록은 수행하지 않았다.
- 운영 시트 변경 전 사본 검사·최신 백업·쓰기 점검을 수행한다. 숨김 관리 탭에는 중복 방지와 이력 연결 정보가 있으므로 임의 삭제하지 않는다.
- 인증 JSON, API 키, PIN/해시, 세션 비밀값, 실제 제출 기록·사진·보고서·전체 기술이관 ZIP은 공개 GitHub에 올리지 않는다. 문서에는 비밀값 대신 환경변수 이름과 준비 절차만 기록한다.
- 다른 PC로 이동하기 직전 사용자가 요청하면 최신 소스와 문서를 확정하고 비공개 데이터·인증정보를 별도 백업한다. 현재는 이동 전 최종 백업을 실행하지 않는다.
- 사용자 지시와 이미 받은 권한을 확인하여 불필요하게 재승인을 요청하지 않는다. 실제 도구 제한과 사용자 승인 부족을 혼동하지 않는다.

- 2026-11-13 사용자 지시: 두 저장소 GitHub Actions를 비활성화하고 모든 운영 워크플로/템플릿을 제거했다. 복구·새 PC 설치·검증을 이유로 Actions를 재활성화하거나 .github/workflows YAML을 만들지 않는다. 로컬 검사와 개별 Render 수동 배포를 사용한다. Render 설정 YAML은 Actions가 아니다. 과거 CI 기록과 새 로컬 검증을 구분한다.
- KYWA 담당자 판정 검토표의 회신은 대기 중이다. 다른 기관에 사례 작성을 요구하지 않으며 기관별 점수표를 KYWA 결과로 일괄 보정하지 않는다.
