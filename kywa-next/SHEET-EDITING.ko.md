# KYWA 평가표 직접 삭제·수정 운영 안내

## 지원 범위

KYWA 평가 탭은 19열(A:R + S 제출자 성명)을 유지한다. 관리자는 행 삭제 또는 A:S 전체 내용 지우기로 평가를 제외할 수 있다. 신규 제출은 마지막 데이터 행 다음에 쌓이고 중간 빈 행을 채우지 않는다. 삭제한 평가의 사진·조치이력·숨김 관리 기록은 복구용으로 보관한다. 이전 제출 요청을 다시 보내도 삭제한 평가는 복원하지 않는다.

위험상황·감소대책 등 셀 수정은 앱 조회에서 반영된다. 빈도·강도·점수·등급이 바뀌면 저장된 기준으로 빈도×강도와 등급을 확정한다. 수정하지 않은 과거 점수·등급은 유지한다. 기준이 불명확한 기록은 관리자 목록에서 **현재 KYWA 기준 적용**을 눌러 확정한다. 개선 후 수치를 새로 입력한 것만으로 완료 처리하지 않는다.

잘못된 날짜·필수 항목·숫자가 있는 행은 ‘시트 확인 필요’에 행 번호와 수정할 항목을 표시한다. 다른 평가와 신규 제출은 계속 처리한다. 문제가 있는 행이 조회 범위에 포함되면 보고서를 만들 수 없다. 시트에서 수정한 뒤 목록 새로고침을 누른다. 메뉴 진입·탭 복귀·보고서 생성/다운로드에서도 최신 내용을 확인한다.

일부 열만 별도 정렬하거나 셀을 다른 평가에 끼워 넣는 작업은 지원하지 않는다. 행 이동·정렬을 운영 절차로 추가하려면 별도 검증한다. 같은 셀을 앱과 시트에서 동시에 수정하지 않는다. Google Sheets에는 일반 DB처럼 조건부 쓰기 잠금이 없으므로, 사전·사후 대조에서 충돌이 발견되면 초안을 보존하고 재확인을 요구한다.

## 내부 구조

- 행 DeveloperMetadata `kywa.assessment.id`가 불변 평가 ID를 연결한다. 행 이동에 따른 번호 변화는 ID와 분리한다. 값과 행 메타데이터는 같은 Google 응답으로 읽는다.
- `_시스템관리`의 `config / row_identity`가 `version: 2`일 때만 새 경로를 사용한다. 다른 기관과 이전 20/24열 경로는 기존 동작을 유지한다.
- `record`에는 마지막 유효 값, 변경 감지 값, 수정 버전, 삭제 상태를 보관한다. 직접 수정 이력에는 변경 전후 값과 시스템 확인 시각을 저장하며, Google 편집자 이름을 추정하지 않는다.
- `request`는 제출 영수증이다. 평가 행과 요청 기록을 한 `batchUpdate`에서 `appendCells`로 추가한다. A열의 짧은 임시 메모로 실제 저장 위치를 확인하고 행 메타데이터 연결 후 메모를 제거한다. 응답 유실 후에는 요청 기록부터 복구하며 다시 행을 추가하지 않는다.
- `edit`는 조치·기준 확정·수치 보정의 복구 기록이다. DeveloperMetadata의 DataFilter로 대상 행의 필요한 셀만 갱신하고, 조치이력과 관리 기록을 함께 확정한다. 동일 작업 ID의 이력은 중복 추가하지 않는다.
- 기준 서식은 숨김 설정에 보관한다. 전체 데이터 행이 삭제되어도 한국 날짜값·Roboto 10pt·열별 서식을 신규 행에 적용한다. 표/필터 범위도 확장한다.
- 보고서는 기록 내용의 서명으로 캐시를 구분한다. 다운로드 전에 같은 조회 범위를 다시 확인하고, 삭제·수정된 기록의 예전 보고서는 다운로드하지 못하게 한다.

## 적용 및 복구

1. 최신 운영 파일의 공유 드라이브 사본을 만들고 삭제·수정·재시도 검사를 한다.
2. KYWA만 신규 앱 쓰기를 점검 상태로 전환한다. 관리자 세션과 CSRF를 사용해 `POST /api/admin/storage-maintenance`에 `enabled=true`를 보낸다. 잠금은 현재 서버의 30분 임시 상태이며 재배포 때 초기화된다.
3. 서버 환경변수를 준비하고 `python -m backend.migrate_row_identity`로 변경 계획을 확인한다. 일치 내용이 모호하면 자동 연결하지 않고 중단한다.
4. `python -m backend.migrate_row_identity --apply`를 실행한다. 도구는 전체 GridData 로컬 JSON과 같은 공유 드라이브의 파일 전체 사본을 만든 뒤 연결한다. 비공개 백업을 GitHub에 올리지 않는다. 이미 준비된 파일에 재실행하면 변경하지 않는다.
5. CI를 통과한 코드를 KYWA에만 배포하고 실제 제출·수정·삭제·재시도·보고서를 확인한다. 점검 잠금이 남아 있으면 `enabled=false`로 해제한다. 평가 탭 값·사진 링크·점수·성명·조치이력이 보존됐는지 대조한다.
6. 실패 시 새 쓰기를 막고 그 시점 파일도 먼저 복사한다. 평가 탭, 행 DeveloperMetadata, `_시스템관리`, 조치이력은 같은 시점의 한 묶음으로 복구한다. 새 코드에서 v2 연결을 제거하거나 옛 코드만 단독 롤백하면 삭제된 관리 기록 때문에 기존 오류가 다시 발생하므로 금지한다. 파일 전체 사본을 임시 운영 대상으로 연결하려면 새로 생긴 제출을 대조·병합한 뒤 대상 ID를 변경한다. 복구 후 기존 사진 폴더는 유지한다.

현재 변경의 로컬·사본·CI·운영 검증 결과는 HANDOFF.md와 CHANGELOG.md를 기준으로 확인한다.
